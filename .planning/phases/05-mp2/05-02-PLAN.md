pyscf_algebra reduction surface (crates/pyscf-algebra/src/oracle.rs, verified):
- `oracle_sum(xs: &[f64]) -> f64` — pairwise tree, fixed `PAIRWISE_CHUNK = 128`, thread-count invariant.
- `oracle_dot(a: &[f64], b: &[f64]) -> f64` — materializes `a[i]*b[i]` then `oracle_sum`; returns `f64::NAN` on length mismatch.
- `oracle_einsum("ij,jk->ik", a, a_shape, b, b_shape) -> Option<Vec<f64>>` — ONLY the binary `ij,jk->ik` case is shipped; other patterns return `None`.
- `pyscf_algebra::gemm` returns `NotYetImplemented{phase:2}` (gemm.rs:17) — NOT usable. Host loops only.

MOCoefficients (crates/pyscf-core/src/mo.rs, verified):
```
pub struct MOCoefficients { pub nao: usize, pub nmo: usize, pub data: Vec<f64>, pub energies: Vec<f64>, pub occupations: Vec<f64> }
```
`data` is COLUMN-MAJOR / F-order: element `C[ao_i, mo_j]` lives at `data[ao_i + mo_j * nao]`. Slicing `co = C[:, :nocc]` is the first `nocc` columns = `data[0 .. nocc*nao]`.

`mol.intor("int2e")` returns F-order `[nao,nao,nao,nao]` (pyscf-gto/src/intor.rs F-order convention) — element `(p,q,r,s)` at `values[p + q*nao + r*nao^2 + s*nao^3]`. Upstream `ao2mo/incore.py:general` (lines 123-128): the `eri_ao.size == nao**4` branch does `einsum('pqrs,pi,qj,rk,sl->ijkl', eri, C0.conj(), C1, C2.conj(), C3)`.

Flat-index discipline model (crates/pyscf-df/src/cholesky_eri.rs:135-153): doc-comment the exact flat-index formula for EVERY tensor at EVERY boundary (Pitfall 3 mitigation).

Ao2moError + the incore.rs/transform.rs stubs were created in plan 05-01. transform_roundtrip.rs has an always-on compile-smoke + an `#[ignore]`'d numeric assertion to un-ignore here.
