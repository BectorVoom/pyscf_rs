<objective>
**Measure the gate before writing it.** `ROADMAP.md` says Phase 16's gate is
`KRCCSD e_corr` to **1e-14**; `PBC-MASTER-PLAN §7` says **1e-8 on He 1×1×2**.
Both are unmeasured guesses, six orders apart, about the same number — and
upstream's own test suite asserts that number at **6 decimals** (`16-CONTEXT
§2`). This is the fourth time this project has found the same defect
(Phases 14, 15, 17); each earlier catch was pre-implementation, which is the
only reason none cost a rewrite.

**This plan writes no Rust.** It runs upstream against itself, records the
achievable floor and upstream's own internal disagreements, and rewrites the
gate in `16-CONTEXT §2`, `ROADMAP.md` and `PBC-MASTER-PLAN §7`/`§8.8`
together.
</objective>

  <name>Task 1: reproduce upstream's own committed anchors</name>
  Assert `pyscf.__version__ == "2.12.1"` in every snippet, as every Phase

  Run `pyscf/pbc/cc/test/test_krccsd.py` and `test_kgccsd.py` against the

  `:180` (`cc_311`), `:226`/`:232` (`ecc_bench` and its supercell half),

  "what upstream asserts" is the first half of the floor.
</task>

<task type="auto">
  <name>Task 2: run-to-run and thread-count spread — the true floor</name>
  `e_corr` is an *iterated* quantity: two independently converged CCSD runs
  take different DIIS paths. Measure, on `diamond` `gth-szv` 2×2×2:

  1. the same script run 5×, same threads — spread of `e_corr`;
  2. `OMP_NUM_THREADS` 1 vs 8 vs 16 — spread of `e_corr`;
  3. `conv_tol` / `conv_tol_normt` ladder (1e-7…1e-11 × 1e-5…1e-9) — where
     `e_corr` plateaus, and whether `t1`/`t2` plateau at the same point;
  4. `cell.precision` 1e-8 (default) vs 1e-13 — 17-01 Gate B found the floor
     was integral-screening-limited, not convergence-limited, and that
     correction is the single most transferable result in the project.

  **This is the number the gate is set from.** A gate tighter than upstream's
  own run-to-run spread is untestable regardless of what any document says.
</task>

<task type="auto">
