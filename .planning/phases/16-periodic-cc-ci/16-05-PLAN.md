Port `pyscf/pbc/cc/kccsd_rhf.py` (1203 l) — `KRCCSD` itself. This is the
phase's centre of gravity: 17-09 is blocked on it by name
(`PBC-MASTER-PLAN §8.9`), 16-08/09/10 all read its amplitudes, and it is what
the phase gate is stated on.

Two things `§8.8`'s one-line entry does not say, both of which change the
implementation rather than decorate it: the ERI build is driven by
`symm_map` (a ~4× that must be there from the first version, not retrofitted),
and it has **three** storage tiers whose boundary a test has to cross.
</objective>

<task type="auto">
  <name>Task 1: `_ERIS` — the seven blocks, three tiers, and symm_map</name>
  Port `kccsd_rhf.py:727-950` into `crates/pyscf-pbc-cc/src/keris.rs`.

  * The seven blocks (`:789-794`, `:819-832`): `oooo`, `ooov`, `oovv`, `ovov`,
    `voov`, `vovv`, `vvvv`. Each is a `KTensor` (16-02 Task 3) whose tier comes
    from its own exact byte count.
  * **The symmetry loop (`:783`, `:798-805`, `:897-914`) is not optional.**
    `khelper.build_symm_map()` is called lazily here, the loop runs over
    `symm_map.keys()` — the orbit representatives — and fills the remaining
    members with `transform_symm`. Transforming all `nkpts³` triples directly
    is ~4× more integral work (`16-REVIEW.md §3`) and it is this plan's single
    largest speed item. It ships in the first version.
  * **`exxdiv` (`16-CONTEXT §3.5`)**: the ERI build runs with the mean field's
    `exxdiv` suppressed and the Madelung correction is re-added to
    `mo_energy` afterwards (`pbc/cc/ccsd.py:41`, `:57-58`). Ship both halves
    together; either alone is quietly wrong, and `graphene` is the fixture
    where it shows.
  * The GDF branch (`:952-990`, `Lpv`) and the non-DF branch are two routes,
    as `kmp2.py:69` is. Both go through Phase 15's `PeriodicDf` ao2mo
    dispatch; neither grows a second fitting pipeline here.
</task>

<task type="auto">
  <name>Task 2: `update_amps`</name>
  `kccsd_rhf.py:68-260`. The `t1new`/`t2new` assembly against 16-04's
  intermediates, under `kconserv`.

  * **`LARGE_DENOM` (`16-CONTEXT §3.3`)**: `_get_epq` (`:263`) fills padded
    entries with `large_num`, so padded orbitals contribute `~1e-28` to the
    amplitude. They are **not** skipped; skipping them is a different program
    and no gate in this phase would catch it.
  * **Contractions are host rayon loops over k-triples with `oracle_*`
    accumulators** (D-PBC-29 clause 2). The standing measurement
    `zgemm-dense-loses-to-host-rayon` records `zgemm_dense` at 6-12× slower on
    the CPU backend — which is the default here — and 1.35e-10 off, outside
    this project's 1e-11 gate. Name the primitive at every site
    (`16-CONTEXT §3.2`).
  * The `nkpts³ · nocc² · nvir²` accumulation is the D-PBC-17 shape;
    `oracle_sum` goes in **now**, not as the retrofit `0bcff45` had to do for
    `ztrace_ab`/`trace_ab`/`trace_dm_v`.
</task>

<task type="auto">
  <name>Task 4: tests</name>
  `crates/pyscf-pbc-cc/tests/kccsd_rhf.rs`:
  1. **Supercell equivalence, no oracle** — `KRCCSD([1,1,2]).e_corr` equals
     `KRCCSD(1×1×2 supercell).e_corr / 2`. Upstream asserts this at 4 decimals
     (`test_krccsd.py:478`). It alone catches a wrong `kconserv` argument
     order, a wrong `t2` index order and a misplaced `1/nkpts`, and it needs no
     PySCF run.
  2. **Γ-point reduction** — at `nkpts = 1` with real orbitals, `e_corr`
     equals `pyscf-ccsd`'s molecular RCCSD to 1e-12. Again oracle-free, and it
     gates the k-generalisation against already-shipped code.
  3. **MP2 initial amplitudes** — `init_amps`' `emp2` equals Phase 15's `KMP2`
     `e_corr` to 1e-12 on the same fixture. A cross-phase consistency check
     that costs nothing and catches a wrong denominator.
  4. **Tier crossing** (`keris_tiers.rs`) — the same fixture built at a
     `max_memory` forcing incore and again forcing spill gives **bit-identical**
     blocks and `e_corr`. Use the fixture 16-01 Task 5 identified as actually
     crossing a boundary; a test that only ever exercises incore is the defect
     `16-REVIEW.md §2.3` names.
  5. **symm_map equivalence** — `_ERIS` built with the symmetry loop and with
     a direct all-triples loop are bit-identical, and the plan logs the
     measured speed ratio against 16-01 Task 6's number.
  6. **`e_corr` vs upstream, PER DF ROUTE**, on `diamond` and the
     all-electron `he_fcc` control, at 16-01's measured tolerance — and the
     port's own `|E(FFTDF) − E(GDF)|` reported as a *ratio* to upstream's own
     inter-route gap, the way 14-VERIFICATION Gate 3 does.
  7. **Determinism (§9.3)** — bit-identical `t1`, `t2` **and** `e_corr` at
     `RAYON_NUM_THREADS` 1 and 8. Gating `e_corr` alone would pass a
     non-deterministic `t2` that happens to converge to the same energy, and
     16-09/10/11 read `t2` directly (`16-CONTEXT §3.7`).
</task>
