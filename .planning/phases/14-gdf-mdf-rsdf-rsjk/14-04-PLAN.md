  <name>Task 2: get_j_kpts</name>
  PORT `:83-171`. Two passes over `sr_loop`:
  `rho[P] = Σ_k Σ_{μν} cderi[k][P,μν] · dm[k][μν]` then
  `vj[k][μν] = Σ_P cderi[k][P,μν]* · rho[P]`, weighted `1/nkpts`, with the
  `sign` from `sr_loop` folded in (the 2-D negative branch). Only the
  **diagonal** k-pairs `(k,k)` contribute to J.
  `hermi = 1` symmetrises at the end; `kpts_band` goes through the existing
  `format_kpts_band`.
</task>

<task type="auto">
  <name>Task 3: get_k_kpts</name>
  PORT `:281-685`. This is the plan's bulk and its risk.
  `vk[ki][μν] = -(1/nkpts) Σ_{kj} Σ_P Σ_{ρσ} cderi[ki,kj][P,μρ] ·
  dm[kj][ρσ] · cderi[ki,kj][P,νσ]*`.
  Three things upstream does that a naive port will not:
  * **the `force_dm_kbuild` / MO-factorised branch** — when occupied MOs are
    available, `dm = C_occ C_occ†` factorises and the contraction drops an
    `nao` factor. Ship the **density-matrix branch only**; the MO branch is a
    performance variant producing the same numbers, and takes
    `NotYetImplemented { phase: 17 }` if selected. Record the cost in the
    summary — Phase 13 had to reverse exactly this kind of "it's only an
    optimisation" call for `FtKernel`, and the reversal was measurement-driven.
  * **`_ewald_exxdiv_for_G0`** is applied AFTER the `cderi` contraction, once,
    on the assembled `vk` — not inside the k-loop. Reuse
    `pyscf_pbc_df::df_jk::ewald_exxdiv_for_g0`.
  * **k-pair reuse.** `cderi[ki,kj]` is loaded once and used for every density
    channel `iset`. Loading it per `(ki, kj, iset)` is the same defect Phase 13
    found in its own `get_k_kpts` (one `FtKernel` per `(ki,kj)` where the table
    depended on the ket alone). Structure the loop so it cannot recur.
</task>

<task type="test">
  <name>Task 5: tests/df_jk_gdf.rs</name>

  1. **`vj`/`vk` Hermiticity, no oracle**, 1e-13 at all 8 k-points.
  2. **The fitting identity, no oracle.** `vj` built from `cderi` equals `vj`
     built by explicitly contracting `GDF.get_eri` with the same density, to
     1e-12. This tests the contraction, not the fit.
  3. **`exxdiv` isolation, no oracle.** `vk(exxdiv = None)` and
     `vk(exxdiv = Ewald)` differ by exactly `madelung · dm`-shaped correction,
     to 1e-13. Phase 13 measured (risk R-15) that this term is ~96 % of the
     matrix difference between builders while barely moving the energy —
     so gate the matrix and the energy **at different levels** and say which
     is which.
  4. **`kpts_band`, no oracle.** `vk` at `kpts_band == kpts` is bit-identical
     to `vk` with `kpts_band = None`.
  5. **Oracle (`PYSCF_ORACLE_VENV`).** `df_jk.get_j_kpts` / `get_k_kpts` /
     `get_jk` vs upstream, `_prefer_ccdf = True`, at **1e-11** on He-fcc and,
     with `exclude_dd_block = False`, at **1e-11** on diamond; ≤ **3e-8** vs
     upstream's default on diamond.
  6. **Oracle — the SCF that closes Gate 1.** Converged `KRHF` energies:
     He-fcc 2×2×2 **−2.80842508664874** to 1e-11; diamond 2×2×2
     **−10.93209469510988** and gamma **−10.14369242019162** to 3e-8 (and to
     1e-11 against `exclude_dd_block = False`).
</task>
