Define `pub enum TensorBackend { InMemory(Box<[f64]>), Spilled(SpillHandle) }`. `SpillHandle` wraps a `pyscf_chkfile::hdf5` temp file + dataset (the `lib.H5TmpFile()`-equivalent) and MUST delete its file in `Drop` (RAII — mirror H5TmpFile auto-delete; 06-RESEARCH.md §"Runtime State Inventory" requires no leftover scratch). Implement `pub fn reserve(&self, shape: &[usize], allow_spill: bool) -> Result<BufferId, BackendError>`: compute `bytes = shape.product() * 8`; first scan the free-list (`pool` Mutex) for a released allocation of `>= bytes` and REUSE it (return its `BufferId`, mark in-use) — this is what makes the heap-alloc count bounded; only if none is free, `try_reserve(bytes)?` (the HARD pre-flight, D-01) then either allocate a fresh `InMemory` buffer (fits budget) OR, when `allow_spill==true` and it would exceed budget, create a `Spilled` backend (HDF5 temp dataset). When `allow_spill==false` and over budget → propagate `MemoryLimitExceeded` (NO silent downgrade — D-01).

Implement `pub fn release(&self, id: BufferId)`: return the buffer to the free-list (mark not-in-use), do NOT drop the `Box<[f64]>`/spill file — so the next `reserve` of a fitting shape reuses it. Keep the existing `PooledAllocation` field but upgrade its inner type from the `_bytes: Box<[u8]>` stub to carry `{ id, backend: TensorBackend, in_use: bool }`.

Add accessors the kernel needs: `pub fn as_mut_slice(&self, id: &BufferId) -> ...` / a read view, so 06-03 can materialize products into the reserved buffer then `oracle_sum` over it (the buffer is the working store; reductions still go through `pyscf-algebra`). Keep `budget_bytes`, `new`, `from_env`, `try_reserve` signatures UNCHANGED (the skeleton doc-comment mandates not restructuring the public surface).

Export `TensorBackend`, `SpillHandle`, `PooledTensor`/`BufferId` from `pyscf-runtime/src/lib.rs`. Keep `pyscf-runtime` cubecl-touch-allowed (it is on the dependency-wall carve-out) but it must NOT name `pyscf-algebra` (wrong direction). Every reduction/contraction over a reserved buffer remains a 06-03+ concern routed through `pyscf-algebra::oracle_sum`.
