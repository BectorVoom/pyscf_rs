<objective>
Fix BLOCKER CR-03: `c2s_coeff` panics unconditionally for l>4 angular momentum (h-shells and above). Called by both `eval_gto_sph_cpu` and `eval_gto_sph_deriv1_cpu`. Through the PyO3 boundary a user supplying cc-pV5Z or any ANO basis aborts the Python process instead of receiving a Python exception. This violates FOUND-07 (never-panic policy).

Purpose: Convert c2s_coeff from `fn(...) -> f64` (panicking) to `fn(...) -> Result<f64, PyscfRsError>` and propagate the Result through the two CPU kernel functions, then through the public `eval_gto_sph` / `eval_gto_sph_deriv1` surfaces. Add a test that proves l=5 returns Err and does not panic.

Output: Modified `eval_gto.rs` with Result-propagating c2s_coeff; new test `c2s_coeff_l5_returns_err_not_panic`.
</objective>
