<objective>
Fix BLOCKER CR-02: The f32 matmul chain in `numint.rs` uses `S::from(x).unwrap_or_else(S::zero)` and `t.to_f64().unwrap_or(0.0)` throughout `nr_rks_inner<f32>` and `eval_rho_scalar<f32>`. When a valid f64 value exceeds `f32::MAX` (~3.4e38), the conversion returns None and the code silently substitutes 0.0 — no warning, no error, wrong result. The D-08 f32 path is described as "honest" (user gets a warn, not silent corruption). Silent 0.0 substitution on overflow is not honest.

Purpose: Replace every `unwrap_or_else(S::zero)` / `unwrap_or(0.0)` in the f32 numeric chain (lines 445-478 and 506-542) with `.ok_or_else(|| PyscfRsError::NumericOverflow { ... })?`. Add `PyscfRsError::NumericOverflow` to error.rs. Both `eval_rho_scalar` and `nr_rks_inner` must propagate `Result` up from any f32 overflow. The f64 path is unchanged.

Output: Modified `error.rs` (new NumericOverflow variant); modified `numint.rs` (f32 chain returns Result on overflow); new test proving overflow produces Err.
</objective>
