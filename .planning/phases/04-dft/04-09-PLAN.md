| Boundary | Description |
|----------|-------------|
| Python callback → Rust driver (DFT-08) | Python subclass overrides invoked from Rust inside the SCF cycle; a panicking/exception-raising Python override must not cause UB |
| PyO3 NumPy boundary | arrays crossing into/out of the bridge hooks |
| Python precision surface (D-08) | the precision getter is read-only; switching is via PYSCF_DTYPE only — no mutable Python entry point that could desync the active scalar mid-run |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-04-09a | Elevation / Tampering | panicking Python override across the FFI seam | mitigate | per-hook `Python::attach`/`Python::detach` (Phase 3 D-03); a Python exception in a hook converts to a Rust `Err` (Phase 3 BIND-09 create_exception path), never a process abort/UB; reuse the Phase 3 catch_unwind discipline |
| T-04-09b | Tampering | NumPy non-contiguous input at the bridge boundary | mitigate | reuse the Phase 3 `to_owned()`-on-non-standard-layout converter (BIND-04) in the KS hooks |
| T-04-09c | Denial of Service | GIL deadlock under free-threaded Python | mitigate | per-hook GIL release seam (Phase 3 BIND-05); the string-only `define_xc_` (D-02) avoids a per-block Python callback inside the grid loop entirely |
