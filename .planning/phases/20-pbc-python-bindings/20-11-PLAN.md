<objective>
**Port the subclass-override contract to k-points — alone, before any driver
depends on it.**

`crates/pyscf-py/src/bridge.rs` already implements the molecular contract:
`PyOverrideBridge` (`:35`) holds Python `self` plus the user's `Mole`, and
`call_hook` (`:57-72`) dispatches every hook through `slf.call_method1` so a
Python subclass override is invoked transparently by MRO —
`get_hcore:75`, `get_ovlp:85`, `get_init_guess:95`, `get_jk:131`,
`get_veff:145`, `get_fock:157`, `eig:190`, `get_occ:208`, `make_rdm1:219`,
`energy_elec:232`, `energy_tot:251`.

`pyscf-pbc-scf` exposes the exact analogue — `trait KOverrideHooks`
(`src/khooks.rs:21`), implemented by all five drivers (`krhf.rs:182`,
`kuhf.rs:188`, `krohf.rs:211`, `kghf.rs:128`, `khf_ksymm.rs:481`) and consumed
by the SCF driver `kernel<H: KOverrideHooks>` (`src/kscf.rs:110`).

**The contract ports 1:1; the payloads do not.** Every hook carries complex,
per-k data (`KMats = Vec<CTensor>`), so this bridge is built on 20-07's
list-of-complex-array conversions, not on `to_density`.

One performance note that is a correctness trap if ignored: the molecular bridge
probes `hasattr` to decide whether an override exists (`bridge.rs:102`). In the
k-point loop that probe runs per hook **per k-point**. `caches.rs:28` exists for
exactly this — reuse it.
</objective>
