<objective>
**Bind the k-symmetry, k-point-helper and tools layers.**

`pyscf-pbc-symm` is 7,195 lines / 211 public items, dominated by **`KPoints`**
(`src/kpts.rs:347`, `build:482`). It is not optional: upstream's
`KRHF`/`KRKS`/`KUKS` all dispatch on `isinstance(arg, libkpts.KPoints)`
(`pbc/scf/__init__.py:68`, `pbc/dft/__init__.py:37-53`), so the shims in
20-12/20-13 cannot branch correctly until this type exists in Python.

`KPoints` carries the IBZ machinery: `nkpts`/`nkpts_ibz`/`nop`/`ops`/`dmats`,
`get_kconserv:851`, `make_ktuples_ibz:979`, `make_k4_ibz:1092`,
`little_cogroups:902`, and `transform_mo_coeff:1365`, `transform_mo_coeff_k:1385`,
`transform_mo_occ:1425`, `transform_mo_energy:1437`.

**One thing must not be "fixed" during binding.** Phase 17 found **four defects
in upstream PySCF 2.12.1's own k-symmetry code**, three of which change a
number — `D-17-09-01` (a T1 term guarded on a stale loop variable, worth
1.117e-10), `D-17-07-01` (an `IndexError` at Γ under the default
`use_ao_symmetry` + time-reversal), `D-17-09-02`. This port deliberately
diverges and `17-VERIFICATION` records it. A binding written to "match upstream
exactly" reintroduces the bugs.
</objective>
