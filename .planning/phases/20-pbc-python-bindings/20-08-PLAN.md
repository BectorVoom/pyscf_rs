<objective>
**Establish the nested module shape once, before eight plans depend on it.**

`crates/pyscf-py/src/lib.rs:50` declares the `#[pymodule]` and `:70-114`
registers seven **flat** submodules — `scf`, `gto`, `dft`, `mp`, `cc`, `grad`,
`geomopt`. PBC needs **nested** ones so that `pyscf._native.pbc.scf` resolves.
That is a different registration pattern in PyO3, and discovering it eight
times in eight plans is eight chances to do it differently.

`crates/pyscf-py/` contains **zero** `pbc` references today.

This plan registers the tree with every child **empty**, and verifies the import
path works before any binding exists. It is deliberately small.

**The libxc trap:** `crates/pyscf-pbc-dft/Cargo.toml:14` takes `pyscf-dft` with
default features on, and `pyscf-dft`'s default is `["libxc"]` — 266 kernels,
~6h, the reason `ci.yml:418` is `if: false`. 20-13 decides that posture. **This
plan must not add `pyscf-pbc-dft` as a dependency**; add only the crates whose
bindings land in 20-09 … 20-12, and let 20-13 add its own.
</objective>
