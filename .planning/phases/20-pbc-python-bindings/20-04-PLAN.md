<objective>
**Name the step where the one genuinely-unmet numeric gate breaks.**

`17-VERIFICATION:126` records, and deliberately does not absorb:

| quantity | target | measured |
|---|---|---|
| `KRKS` ksymm vs full BZ, **FFTDF** | 1.8e-11 … 1.6e-10 | `3.109e-14` ✓ |
| `KRKS` ksymm vs full BZ, **GDF** | same | **`1.432e-06` — NOT MET** |

The FFTDF arm of the *identical* comparison passes by five orders. So the fault
is specific to the GDF route, not to k-symmetry.

17-08's own diagnostic (`krks_ksymm.rs:844-956`) already narrowed the mechanism:
GDF's `kpts_band` route rebuilds `_cderi` over `kpts ∪ kpts_band`
(`df.py:299-313`), while FFTDF's band path is analytic. That diagnostic also
carries the warning this plan must obey — **`kpts_band` must be a STRICT subset
or `get_jk` short-circuits and the test measures nothing** (`:918`). A vacuous
pass here would be the same defect class the whole phase exists to correct.

**This plan measures and names the step. It does not fix.** A fix chosen before
the failing step is named is a guess.
</objective>

<tasks>

<task type="auto">
  <name>Task 1: assert the comparison is not vacuous</name>
  Before measuring anything, assert in the harness:
  - `kpts.nkpts_ibz() < kpts.nkpts()` — the fixture actually folds;
  - the band set is a **strict** subset of the sampling set.

  If either fails the whole measurement is meaningless. Record the two counts
  as integers, not as a ratio.
</task>

<task type="auto">
  <name>Task 2: bisect by route, in this order, from ONE converged mean field</name>
  Use a single converged density for every arm so nothing measures SCF drift.
  Record `max |Δ|` at each step and stop at the first &gt; 1e-9:

  1. `_cderi` built over the IBZ vs over the full BZ — compare the fitted
     3-centre tensor directly, before any J/K contraction.
  2. `get_j` alone, IBZ vs full BZ.
  3. `get_k` alone, IBZ vs full BZ.
  4. the `kpts_band` rebuild path vs the direct path, at a strict-subset band
     set.

  **Name the first step that exceeds 1e-9.** That is this plan's deliverable.
</task>

<task type="auto">
  <name>Task 3: run the same four steps on the FFTDF arm as a control</name>
  FFTDF passes at `3.109e-14`. Running the identical bisect on it proves the
  harness can resolve the difference, and isolates which step is GDF-specific.
  A control that also shows 1e-6 would mean the harness is wrong, not the route.
</task>

<task type="auto">
  <name>Task 4: classify the result</name>
  Exactly one of:

  - **(a) A defect** — a specific contraction, index or phase is wrong. Record
    the step, the expected and actual values, and hand it to a follow-up fix.
  - **(b) A fitting difference** — the GDF auxiliary fit genuinely differs
    between an IBZ-restricted and a full-BZ build, as the FFTDF/GDF
    `1.222e-03` fitting error is genuinely a property of DF. Then the gate is
    **wrong**, not the code: restate it with provenance, in the style of
    `14 measurements:121`, and record the restatement in 20-01's floor table.

  Do not pick (b) merely because (a) is hard. The control in Task 3 and the
  step named in Task 2 must support the choice.
</task>

</tasks>
