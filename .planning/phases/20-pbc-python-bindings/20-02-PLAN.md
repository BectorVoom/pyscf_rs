<objective>
**Measure what the CI job in 20-03 will run, before writing the job.**

`grep -c pbc .github/workflows/ci.yml` returns **0** — no CI job touches any
periodic code. Meanwhile **161 PBC gates are `#[ignore]`d**:

| crate | ignored | crate | ignored |
|---|---:|---|---:|
| `pyscf-pbc-cc` | 59 | `pyscf-pbc-scf` | 16 |
| `pyscf-pbc-dft` | 24 | `pyscf-pbc-mp` | 13 |
| `pyscf-pbc-gto` | 24 | `pyscf-pbc-ci` | 1 |
| `pyscf-pbc-df` | 22 | `pyscf-pbc-symm` | 1 |
| | | `pyscf-pbc-tools` | 1 |

~88 are ignored **solely** for want of `PYSCF_ORACLE_VENV`. Nine phases of
measurement are documentation, not enforcement.

A job cannot be written without knowing what each gate costs — some are
seconds, and `kscf.rs:513` is *"~30 min at the default mesh"*. **This plan
measures; 20-03 writes the job.**

There is also a live trap to disarm first. `tests/oracle/requirements.txt:14`
pins `pyscf>=2.6`; the `*-oracle-upstream-manual` jobs `pip install
"pyscf>=2.5"`. Both resolve to **2.14.0** — the version Phase 11 pinned
*against*. These are exactly the files 20-03 would be copied from. CI already
pins `pyscf==2.12.1` correctly at `ci.yml:284`, `:326`, `:328`.
</objective>

<task type="auto">
  <name>Task 2: enumerate the 161 gates</name>
  ```bash
  grep -rn '#\[ignore' crates/pyscf-pbc-*/tests/*.rs
  ```
  Record every hit as `crate :: test file :: test name` in
  `measurements/pbc-oracle-tiers.md`. The count must total 161; a different
  total means the tree moved and the table must say so.
</task>

<task type="auto">
  <name>Task 3: measure each gate's runtime</name>
  Run each with the venv gate on, **naming the test target explicitly**:

  ```bash
  export CARGO_TARGET_DIR=/home/user/.cargo-target-gate   # NEVER /tmp (16 GB RAM tmpfs)
  PYSCF_ORACLE_VENV=1 cargo test -p <crate> --release \
      --test <target> -- --ignored --nocapture <test_name>
  ```

  A bare `--tests` at high parallelism has been OOM-killed in this workspace —
  name the target. Confirm `exit = 0`; the process merely being gone is not
  success. Never cap memory with `ulimit -v` (it makes every CubeCL launch
  panic); use `systemd-run --scope -p MemoryMax=` if a cap is needed.

  Record wall-clock **and** pass/fail with the measured deviation.
</task>

<task type="auto">
  <name>Task 4: assign tiers by runtime alone</name>
  - **T1** &lt; 30 s — every push/PR.
  - **T2** 30 s - 5 min — nightly `schedule`.
  - **T3** &gt; 5 min — `workflow_dispatch` only.

  Tiering is by cost, never by outcome. A fast failing gate is **T1 and
  failing**, not demoted.
</task>

<task type="auto">
  <name>Task 5: encode the tier in the ignore reason</name>
  Rewrite each reason string to carry its tier while keeping the venv gate as
  the skip mechanism, e.g.
  `#[ignore = "T2: needs PYSCF_ORACLE_VENV + the vendored upstream PySCF"]`.
  `oracle_python()` returning `None` must still **skip, never fail**.
</task>

<task type="auto">
  <name>Task 6: list the failures for 20-04</name>
  Any gate failing under a correct 2.12.1 oracle gets a row: test name,
  measured deviation, expected floor from 20-01's table. **Do not loosen any
  tolerance.** This list is 20-04's input.
</task>

</tasks>
