<objective>

**Fix the NWChem `.dat` parser to support GENERAL CONTRACTIONS — the root cause
of the 03-13 minao heavy-atom caveat, and a latent correctness bug for ALL
generally-contracted bases.**

Diagnosis (this session): `ano.dat`'s O S-block has 8 general-contraction
coefficient columns, but `nwchem.rs` reads only `cols[1]`
(`exps.push(cols[0]); coeffs.push(cols[1])`), silently discarding columns 2..8.
So ANO/ANO-RCC (and any generally-contracted basis) load TRUNCATED to a single
contraction per block. Consequences:
- minao under-normalizes for atoms needing >1 contraction per l (O 1s+2s →
  loaded as 1 s → H2O `Tr(dm·S)≈7.9` vs nelec 10; it still converges, but the
  guess is wrong).
- Any correlation/ANO calculation using these bases silently uses the wrong
  basis functions.

The fix: when a primitive block carries `exp + N` coefficient columns, emit `N`
contractions (one per column, sharing the exponents) into the `ShellSpec`. The
downstream `ParsedBasis`/cintx structures ALREADY support multiple contractions
(`spec.coeffs` is a `Vec` of columns — see `projection.rs`), so this is a parser
fix, not a data-model change.

**Scope/risk:** this touches the parser used by EVERY `.dat` basis. Segmented
bases (one coeff column per block) MUST be unchanged — an explicit regression
guard is required. cintx must evaluate nctr>1 shells correctly (verify).

No new crate dep; libxc NEVER compiled.
</objective>

**Root cause (nwchem.rs, `CurrentShell::Single` primitive-row branch):**
```rust
exps.push(cols[0]);
coeffs.push(cols[1]);   // BUG: only the first contraction column
```
`cols` = whitespace-split row = `[exp, c1, c2, ..., cN]`. For a general
contraction N>1; for segmented N=1.

**ParsedBasis / ShellSpec:** `spec.coeffs` is `Vec<Vec<f64>>` (or equivalent —
confirm exact type) — one inner Vec per contraction column, each length nprim.
`projection.rs::build_atoms_and_shells_with_base` already iterates `for col in
&final_coeffs` and `nctr = spec.coeffs.len()`, and `make_env::normalise_contractions`
takes `(l, exps, coeffs)`. So the consumer side handles nctr>1 already.

**Parser shape to produce:** for a block with N coeff columns, accumulate N
parallel coefficient vectors (column-major: `coeffs[c][p]` = row p, column c+1),
each sharing `exps`. Emit a ShellSpec with `coeffs` = those N vectors. The
`SharedSP` (`sp` shells: exp + s_coeff + p_coeff) branch is a DISTINCT case
(two different l's) — do not conflate; general contraction is N columns of the
SAME l.
