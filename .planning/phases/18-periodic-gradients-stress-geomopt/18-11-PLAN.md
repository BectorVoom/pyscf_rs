<objective>
**The stress half's missing kernel.** All four stress modules obtain their AO
strain derivatives from
`cell.pbc_eval_gto('GTOval_sph_deriv%d_strain_tensor' % deriv, ...)`
(`rks_stress.py:127-147`), which resolves to
`pyscf/lib/pbc/grid_ao.c:431 PBCeval_cart_for_strain_tensor_iter`.

`grep -rn "strain_tensor" crates/` returns **nothing**. `PBC-MASTER-PLAN §8.10`
costs this at zero while correctly observing that "stress needs no derivative
integrals at all" — true, and the reason is that it needs a derivative *AO
family* instead.

This blocks 18-12 and 18-13, and it is the phase's only new cubecl kernel.
</objective>

<task type="auto">
  <name>Task 1: the strain-tensor AO kernel, `deriv = 0`</name>
  Output shape per `grid_ao.c:442` and `rks_stress.py:130-131`:
  `(nkpts, 3, 3, comp, ngrids, nao)` with
  `comp = (deriv+1)(deriv+2)(deriv+3)/6` — so `comp = 1` at `deriv = 0` and
  `comp = 4` at `deriv = 1`, and the `3 × 3` axis is the strain tensor
  `ε_{xy}`.

  Ship sph and cart. Upstream tests both separately
  (`test_rks_stress.py:125 test_eval_ao_cart`, `:142 test_eval_ao_sph`) because
  the transform interacts with the strain index.

  Gate at the component level, against upstream's own construction: build the
  two displaced cells with 18-02 Task 5's `_finite_diff_cells` at
  `disp = 1e-5`, evaluate the ordinary AO on each, and compare the central
  difference to this kernel's output. Upstream's own acceptance for this is
  `< 1e-8` (`test_rks_stress.py:388`) — **Gate A**. Nine `(x,y)` components,
  each checked.
</task>

<task type="auto">
  <name>Task 2: `deriv = 1`, and the grid-response term that is NOT the kernel's job</name>
  `deriv = 1` gives `comp = 4`, and the stress callers then **add** the
  grid-response term on top:

  ```python
  rks_stress.py:215   ao_strain[:,:,0] += einsum('xig,yg->xyig', ao[1:4], coordsT)
  rks_stress.py:216   ao_strain[:,:,1] += einsum('xig,yg->xyig', ao[4:7], coordsT)
  ...
  ```

  That addition belongs to the **caller** (18-12), not to this kernel — it is
  the response of the grid points to the strain, not of the basis function.
  Shipping it inside the kernel would double-count it for any future caller
  that does its own grid response, and would make Gate A's finite difference
  disagree with the kernel by exactly that term.

  Gate at `deriv = 1` against `test_rks_stress.py:160`/`:178`'s construction,
  again at `< 1e-8`, and separately gate the caller-side grid-response addition
  against `:196 test_eval_ao_grid_response`.
</task>

<task type="auto">
  <name>Task 3: the fusion decision (D-PBC-30 clause 5)</name>
  Upstream evaluates the AO table **twice** over the same grid block: once via
  `block_loop(..., deriv+1)` and once via `_eval_ao_strain_derivatives(...,
  deriv=deriv)` (`krks_stress.py:170-173`). The two share every radial and
  exponential factor. Because this port writes the strain kernel from scratch,
  it can emit both in one pass.

  **Ship the fused kernel only if 18-01 Task 6 measured a win.** This project
  has already measured that in its collocation kernels *"buffer traffic, not
  exp, was the wall-clock sink"* — if that holds here, fusing saves one pass
  over a 46-component buffer, which is real but bounded, and not the
  exponentials, which is where the intuition would have put it.

  Either way, cite 18-01 Task 6's number in the module doc. If the fused kernel
  ships, it must produce **bit-identical** output to the two-pass version on a
  reference block, and a test asserts that — a fusion that changes the last
  bits changes every stress gate downstream.
</task>

<task type="auto">
  <name>Task 4: wire it into `pbc_eval_gto`</name>
  Extend `crates/pyscf-pbc-gto/src/eval_gto.rs`'s dispatcher to accept
  `GTOval_{sph,cart}_deriv{0,1}_strain_tensor`, returning the reshaped
  `(3, 3, comp, ngrids, nao)` per k-point that `_eval_ao_strain_derivatives`
  produces (`rks_stress.py:143-146`).

  Anything else in that name family is a **named refusal**, not a fall-through
  — `deriv >= 2` has no upstream caller and no oracle, and a silent
  fall-through to the non-strain family is the R-14 failure mode in a different
  costume.
</task>
