<objective>
**The XC and pseudopotential strain terms, the reported units, and the gates.**

Split out of 18-12 so the shared-symbol layer and the closed form that replaces
36 lattice sums are reviewed separately from the terms built on them. 18-12
lands the foundation; this plan lands `get_vxc`, the PP strain terms, `kernel`,
and the gates that prove all of it.

Two things here have bitten this project before and are called out in the
`must_haves` rather than left to care: the **units** (upstream asserts a
pressure; both `ROADMAP` and `§8.10` state an energy, which is the wrong
dimension and ~8x tighter read as one), and **Gate A's tiering** (a flat 1e-8
is `:388`'s `get_pp` number, the single loosest assertion in a file whose other
twenty-one are at 1e-9 or 2e-9).
</objective>

<task type="auto">
  <name>Task 1: `get_vxc` — fuse the XC contraction, keep two arrays full-grid (clause 7)</name>
  Port `:148-290`. Upstream allocates `rho1 = np.empty((3,3,nvar,ngrids))`
  (`:191`) over the full grid. Its only full-grid consumers are
  `einsum('xyng,ng->xy', rho1, vxc)` (`:259`) and, for the `with_j`/`with_nuc`
  terms, `rho1[:,:,0]` alone (`:267`, `:276`, `:287`).

  The XC functional is **pointwise in `rho0`**, so `vxc[:,g]` depends only on
  `rho0[:,g]` and the first contraction can be evaluated per block and
  accumulated into the 3×3 output. Keep full-grid: `rho0` (needed by
  `pbctools.fft(rho0[0], mesh)` at `:264`, and no larger than a normal DFT run
  already carries) and `rho1[:,:,0]`. Drop `rho1[:,:,1:nvar]` — a **4× (GGA) /
  5× (MGGA)** cut on that array.

  **Block accumulation changes the summation order** relative to the full
  einsum. The 3×3 accumulator must route through a materialised per-block
  partial array and `pyscf_algebra::oracle_sum` — the D-PBC-17 pattern applied
  to `ztrace_ab`/`trace_dm_v` in commit `0bcff45`, and required of
  `symmetrize_density` by `17-CONTEXT` *"from the first version, not as a
  retrofit."*

  Also fold the post-loop scalings into the block: `rho0[1:4] *= 2`,
  `rho0[4] *= .5`, `rho1[:,:,4] *= .5`, `rho1 *= 2.` (`:250-256`). The last one
  applies to the whole array and is easy to lose when the array stops being
  whole.

  Honest sizing (`18-REVIEW §3.8`): this is a 4–5× cut on a 6.7 MiB
  (`ngrids = 24389`) to 59 MiB (`60³`) array — an order of magnitude below
  clauses 1 and 3. It is done because it is nearly free once the loop is being
  rewritten for Task 2, not because it is where the memory is.
</task>

<task type="auto">
  <name>Task 2: the pseudopotential strain terms</name>
  Port `_get_vpplocG_strain_derivatives` (`:292-308`) and
  `_get_pp_nonloc_strain_derivatives` (`:309-386`, including the nested
  `eval_pp_nonloc` at `:329`). The `with_nuc` branch (`:277-288`) chooses
  between the pseudopotential path and the all-electron `get_SI`/`coulG` path;
  both ship, and `graphene` (dimension 2) is the fixture that keeps the second
  honest.

  `ewald` (`:387-397`) is the strain derivative of the Ewald sum, distinct from
  18-03's `ewald_nuc_grad` (which is the *nuclear-coordinate* derivative).
  Two different derivatives of one energy; give them names that cannot be
  confused at a call site.
</task>

<task type="auto">
  <name>Task 3: `kernel` and the reported units</name>
  Port `:398-462`. **The result is a pressure.** Upstream's own acceptance is
  `abs(dat[i,j] - (e1-e2)/2e-3/vol) < 1e-6` (`:406`) — `dE/dε` divided by the
  cell volume, Ha/Bohr³. `ROADMAP.md` and `§8.10` both state the gate as
  "1e-5 Ha", which is the wrong dimension and, read as an energy, ~8× tighter
  than upstream's own number (`18-CONTEXT §2.2`).

  Return Ha/Bohr³, say so in the type's doc comment, and name `vol` in the
  gate expression so the dimension cannot drift again.

  **MGGA is supported here** (`:176-178`), unlike the gradient half, which
  refuses it (18-07 Task 1). That asymmetry is upstream's shape; record it in
  the module doc so nobody reconciles the two.
</task>

  * **Gate A**, component level, against `_finite_diff_cells` at `disp = 1e-5`.
    Fourteen component tests — port them all; each one localises a wrong term
    to a single function, and the end-to-end gate does not. **Gate A is three

    stated a flat 1e-8, which is `:388`'s `get_pp` number — the single loosest
    assertion in a file whose other twenty-one are at 1e-9 or 2e-9):

    | tier | tol | tests |
    |---|---|---|
    | **A1** | `1e-9` | `test_ovlp` (`:37`), `test_kin` (`:73`), `test_weight` (`:109`), `test_coulG` (`:118`), `test_eval_ao_*` (`:125`–`:196`, from 18-11), `test_lattice_vector_derivatives` (`:242`), `test_get_vxc_{lda,gga,mgga}` (`:260`, `:279`, `:298`) |
    | **A2** | `2e-9` | `test_get_j` (`:317`), `test_get_nuc` (`:342`) |
    | **A3** | `1e-8` | `test_get_pp` (`:365`) |

    Each test's doc comment names the upstream assertion line its tolerance
    inherits. A measured floor above its tier is a finding with a number, not a
    licence to fall back to A3.
  * **Gate D**, end to end, `< 1e-6 Ha/Bohr³` at `disp = 1e-3`, for LDA, GGA
    and MGGA (`:390`, `:408`, `:426`), on upstream's own randomised-lattice
    cells (`np.random.seed(5)`, `:393`) so the off-diagonal strain components
    are actually exercised — a cubic cell makes several of them vanish.
</task>
