<task type="auto">
  <name>Task 1: `get_veff_ip1`</name>
  Port `multigrid_pair.py:748-860`. Structure: `_eval_rhoG` at `deriv = 0`
  (LDA/HF) or `1` (GGA) → multiply by `coulG` → add `vpplocG_part1` when
  present → inverse-FFT to `rhoR` with the `1/weight` rescale (`:791-793` — the
  comment there explains why the weight is divided out, and getting it backwards
  is a silent factor of `vol/ngrids`) → evaluate XC → collocate back.

  Three refusals to port verbatim:
  * `:749` — `isinstance(kpts, KPoints)` raises. That is 17-09's deferral;
    honour it, do not work around it.
  * `:766` — anything above GGA raises. Consistent with 18-07's meta-GGA
    refusal, and for the same reason.
  * `:786-787` caches `mydf.rhoG` for the core-density gradient, which
    `vpploc_part1_nuc_grad` then reads. That is a real cross-call dependency,
    not an optimisation: model it explicitly (a returned handle or an
    `&mut self` field), never as an implicit side channel.

  Collocation kernels go in `crates/pyscf-kernels/src/pbc/multigrid_grad.rs`
  per ALG-06 — `pyscf-pbc-dft` may not name cubecl (`17-CONTEXT`'s corollary).
</task>

<task type="auto">
  <name>Task 2: `get_nuc_ip1` and `get_nuc_nuc_grad` — batch the atom loop</name>
  `get_nuc_ip1` (`:893-895`) is `get_nuc(mydf, kpts, deriv=1)` — three lines
  once `get_nuc` grows a `deriv` argument (`:861-892`), which the port's
  `pair.rs:994` `get_nuc` does not have.

  `get_nuc_nuc_grad` (`:896-921`) carries an explicit **`# TODO improve
  performance`** on its per-atom loop (`:916-919`):

  ```python
  for ia in range(cell.natm):
      vG = 1j * np.exp(1j * np.dot(Gv, coords[ia])) * charge[ia] * coulG * Gv.T
      grad[ia] = np.dot(vG, rhoG).real
  ```

  Each iteration allocates a fresh `(3, ngrids)` complex array and re-evaluates
  the structure factor. `rhoG` is already hoisted; the structure factors are a
  `get_SI`-shaped `(natm, ngrids)` batch this port already computes elsewhere,
  and the whole loop is one `(natm, 3) ← (natm, ngrids) × (3, ngrids)`
  contraction. **Batch it.** Same ruling shape as `16-REVIEW §2.4` — upstream's
  own TODO is not a specification.

  The accumulation routes through `oracle_sum` over a materialised per-atom
  partial buffer (D-PBC-17).
</task>

</task>

  escalates only if it completes. **If a run is SIGKILLed, that is the
