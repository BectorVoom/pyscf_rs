<task type="auto">
  <name>Task 2: zgemm (D-PBC-03)</name>
  `crates/pyscf-algebra/src/zgemm.rs`:
  - `zgemm_dense(client, a: &amp;CTensor, b: &amp;CTensor, m, k, n) -> Result&lt;CTensor, AlgebraError&gt;`
    computes, in this exact order:
    `t1 = gemm_dense(a.re, b.re)`, `t2 = gemm_dense(a.im, b.im)`,
    `t3 = gemm_dense(a.re, b.im)`, `t4 = gemm_dense(a.im, b.re)`,
    then `re[i] = t1[i] - t2[i]`, `im[i] = t3[i] + t4[i]`.
    **Do not reorder, do not fuse, do not use the 3-multiplication Karatsuba form.**
    Put a doc comment citing D-PBC-03 and the bit-parity reason.
  - `zgemm_h_dense(client, a, b, m, k, n)` — computes `Aᴴ · B` by materialising `Aᴴ`
    with `transpose_dense` + negating `im`, then calling `zgemm_dense`. Do not fuse.
</task>

  <name>Task 5: zeigh, zcholesky, zsolve_linear (D-PBC-04)</name>
  `crates/pyscf-algebra/src/zeigh.rs`:
  1. **Always** implement `zeigh_gen_embedding(f, s, n)` — the real 2n x 2n route from
     PBC-MASTER-PLAN §5.3. Steps: build `M = [[Hr, -Hi],[Hi, Hr]]` and the same for `S`,
