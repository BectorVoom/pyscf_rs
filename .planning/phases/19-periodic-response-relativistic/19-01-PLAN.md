<objective>
**Measure the floors before writing any gate.**

`ROADMAP.md:465` demands the KRHF-TDA lowest excitation match upstream to
**1e-15 eV**. One f64 ulp at a 5 eV excitation is `8.9e-16`, so that is about
**one ulp** - it demands bit-identical arithmetic to NumPy/LAPACK through an
SCF, a response build and a Davidson solve. `12-VERIFICATION` recorded the best
result anywhere in this port as **221 ulp**.

It is also ten orders tighter than upstream's own suite, whose modal
`pbc/tdscf` assertion is **5 decimals** (15 of 42 assertions; the tightest
anywhere is 10). `pbc/adc` asserts at **4 decimals** in 58 of its 80.

This is the eighth gate-before-measurement defect this project has found.
**This plan writes no Rust.**
</objective>

<tasks>

<task type="auto">
  <name>Task 1: reproduce upstream's own anchors, per family</name>
Run each of `pbc/{tdscf,gw,adc,x2c}/test/` against the vendored 2.12.1 tree and
record, to all 17 digits, every excitation energy, quasiparticle energy, ADC
root and X2C one-electron energy the suites pin - **and separately the decimal
count each assertion actually uses**.

The gap between *what upstream pins* and *what upstream asserts* is the floor.
</task>

<task type="auto">
  <name>Task 2: upstream against itself: the solver spreads</name>
For each family, vary only the solver controls and record the spread:
Davidson `conv_tol` and `nroots` for TDA/TDHF and ADC; the frequency grid size
for GW AC; the contour parameters for GW CD.

Phase 16 measured upstream's own `nroots` spread at `5.11e-7` for EOM roots -
expect the same order here. **A gate tighter than upstream's own spread cannot
be met by any implementation.**
</task>

<task type="auto">
  <name>Task 3: the AC-vs-CD split, measured not assumed</name>
`krgw_ac` and `krgw_cd` are different approximations to the same self-energy.
Run both on one cell and record `|E_AC - E_CD|` per quasiparticle.

If that split exceeds the per-route floor - as the GDF/FFTDF route split did in
Phase 16 at `9.22e-4 Ha` - then a route-blind GW gate measures the split rather
than the port, and Gate C must be stated per route. Record the number either
way.
</task>

<task type="auto">
  <name>Task 4: write the gates and restate the documents</name>
Write `measurements/README.md` in 17-01's format: one section per gate A-E,
each with the measured floor, the snippet that produced it, the chosen
tolerance, and the margin stated.

Then edit, in one pass: `ROADMAP.md:465` (strike `1e-15 eV`),
`PBC-MASTER-PLAN §7`'s Phase-19 row and `§8.11`'s header. All three must read
identically when this plan closes.
</task>
