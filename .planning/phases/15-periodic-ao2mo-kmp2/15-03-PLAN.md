<objective>
The bookkeeping layer of KMP2: `nocc`/`nmo` per k-point, the frozen-core mask,
the padding convention, and the one place where `KScfResult`'s MO coefficients
become `df_ao2mo::MoCoeff`.

Port target: `pyscf/pbc/mp/kmp2.py` — `_padding_k_idx` (:228), `padding_k_idx`
(:276), `padded_mo_energy` (:332), `padded_mo_coeff` (:354),
`_frozen_sanity_check` (:376), `get_nocc` (:401), `get_nmo` (:461),
`get_frozen_mask` (:517), `_add_padding` (:555).

**Nothing here computes an energy, and everything here can silently corrupt
one.** Two of the three worst defects Phase 14 caught were of exactly this kind
— a storage-order misread worth +6 306 866.73 Ha, and a padding/rank assumption
(`get_naoaux`) that was stricter than upstream. Both were invisible to every
gate that existed at the time. This plan is where Phase 15 pays that tax
up front.
</objective>

<task type="auto">
  <name>Task 2: crates/pyscf-pbc-mp/src/frozen_k.rs — nocc, nmo, frozen mask</name>
  * `FrozenK` — the k-resolved frozen specification. Upstream's `mp.frozen`
    accepts four shapes (`kmp2.py:424-441`): `None`, an `int`, a flat list of
    `int`, and a **per-k-point list of lists**. `pyscf_mp2::Frozen` covers the
    first three; the fourth is periodic-only. Express it as

    ```rust
    pub enum FrozenK { Uniform(pyscf_mp2::Frozen), PerKpt(Vec<Vec<usize>>) }
    ```

    so the molecular vocabulary is reused (RULE: one spelling per concept) and
    the periodic shape is additive. `Frozen::{Auto, Window}` have no periodic
    consumer in `kmp2.py`; accept them in the type and return
    `NotYetImplemented { phase: 15, what: "frozen='auto'/'window' at k-points" }`
    rather than guessing a semantic.
  * `frozen_sanity_check(frozen, mo_occ, kpt_idx)` — PORT `:376-399`. All four
    of its errors are user-facing and their messages should survive the port:
    the duplicate check, the out-of-range check, and the `nocc > 0` assertion.
  * `get_nocc(mo_occ, frozen, per_kpoint) -> NoccResult` — PORT `:401-458`.
    **`kmp2.py:416-421` runs BEFORE the `_nocc` cache check**: the fractional
    occupation refusal fires even when `nocc` is overridden. Port that order.
    Upstream's message names `mf.smearing_method`; this port's equivalent is
    `Krhf.smearing` / `Kuhf.smearing` (`krhf.rs:34`, `kuhf.rs:37`), so say that
    instead — the point of the message is to tell the user what to turn off.
    Note the two different frozen-counting rules at `:429-435` and `:441-448`:
    both count `frozen <= max_occ_idx`, i.e. **only frozen orbitals below the
    highest occupied one reduce `nocc`**. That is not the same as `len(frozen)`.
  * `get_nmo(mo_occ, frozen, per_kpoint) -> NmoResult` — PORT `:461-514`.
    The `per_kpoint = false` branch (`:509-512`) is
    `max(nocc) + max(nmo − nocc)` and **is not `max(nmo)`**; upstream's own Note
    at `:466-469` says why. Transcribe that Note into the doc comment.
  * `get_frozen_mask(mo_occ, frozen) -> Vec<Vec<bool>>` — PORT `:517-552`.

  Every branch that upstream ends with `raise NotImplementedError` ends here
  with `NotYetImplemented`, never with a default.
</task>

<task type="auto">
  <name>Task 3: crates/pyscf-pbc-mp/src/padding.rs — the convention</name>
  * `padding_k_idx(nmo: &[usize], nocc: &[usize], kind: PaddingKind) -> PaddingIdx`
    — PORT `_padding_k_idx`, `:228-273`.

    **Transcribe the `padding_k_idx` docstring table (`kmp2.py:288-305`) into
    the Rust doc comment verbatim.** It is the only readable statement of the
    convention anywhere, and the two `assert`-able consequences are worth
    stating in prose beside it:
    - occupied: `0 .. k_o` — **bottom-aligned**;
    - virtual: `dense_v − k_v .. dense_v` — **top-aligned**;
    - so the padding sits at the Fermi level, between the two blocks, and the
      `joint` form is `[0..k_o] ++ [dense_nmo − k_v .. dense_nmo]`.

    `PaddingKind::{Split, Joint}` as an enum, not a `&str` — upstream's
    `ValueError` on a bad `kind` becomes unrepresentable.
  * `padded_mo_energy(mo_energy, frozen_mask, joint_idx, nmo) -> Vec<Vec<f64>>`
    — PORT `:332-352`. Note the shape: the result is `(nkpts, dense_nmo)` and
    the *source* is `mo_energy[k][frozen_mask[k]]`, i.e. frozen orbitals are
    removed BEFORE padding. Zeros elsewhere.
  * `padded_mo_coeff(mo_coeff, frozen_mask, joint_idx, nmo) -> Vec<MoCoeff>`
    — PORT `:354-374`. Same, on the MO axis only; the AO axis is untouched.
  * `add_padding(...)` — PORT `_add_padding`, `:555-565`, including its
    condition: padding is applied when `frozen` is set **or** when some
    `mo_coeff[k]` does not already have `dense_nmo` columns. Do not
    unconditionally pad; upstream does not, and `KMP2.kernel` calls this on
    coefficients that may already be padded.
</task>

<task type="auto">
  <name>Task 4: crates/pyscf-pbc-mp/src/moref.rs — the ONE storage-order conversion</name>
  This module exists so that the column-major/row-major conversion has exactly
  one implementation and one test.

  ```rust
  /// `KScfResult.mo_coeff[k]` (COLUMN-MAJOR nao×nmo, pyscf-pbc-scf/src/types.rs:119)
  /// -> `df_ao2mo::MoCoeff` (ROW-MAJOR, df_ao2mo.rs:88-96).
  pub fn mo_coeff_from_kscf(c: &CTensor, nao: usize, nmo: usize) -> MoCoeff;

  /// The MO-column slice `[lo, hi)` of a `MoCoeff` — `mo_coeff[k][:, :nocc]`
  /// and `[:, nocc:]` (kmp2.py:99-102).
  pub fn mo_slice(m: &MoCoeff, lo: usize, hi: usize) -> MoCoeff;

  /// `KScfResult`'s per-spin block for KUHF: `mo_*[idx(set, k)]`.
  pub fn spin_block(r: &KScfResult, set: usize) -> KMoRef<'_>;
  ```

  `KMoRef` bundles `(mo_energy, mo_coeff, mo_occ)` for one spin channel over all
  k-points, so nothing downstream re-derives the `idx(set, k)` arithmetic.

  **Do not write a `transpose` helper and call it done.** The failure mode is
  not "the transpose is wrong"; it is "the transpose was never called", or was
  called twice. Task 5 test 6 is written to catch that specifically.
</task>

  <name>Task 5: crates/pyscf-pbc-mp/tests/padding.rs + tests/moref.rs</name>

  **tests/padding.rs** — tier-1 first.

  1. **The upstream docstring example, no oracle.** `nmo = [6,6,5]`,
     `nocc = [2,3,2]`. Assert `padding_k_idx(kind=Split)` is exactly
     `([0,1], [0,1,2], [0,1])` and `([0,1,2,3], [1,2,3], [1,2,3])`, and
     `kind=Joint` is `([0,1,3,4,5,6], [0,1,2,4,5,6], [0,1,4,5,6])`. Those are
     upstream's own printed outputs at `kmp2.py:311-315` — a committed tier-2
     fixture that needs no interpreter.
  2. **Dense dimensions, no oracle.** For the same input, `get_nmo(per_kpoint=false)`
     is `7` and `get_nocc(per_kpoint=false)` is `3`, exercising the
     `max(nocc) + max(nvir)` rule that is not `max(nmo)`.
  3. **Padding is a no-op when it should be, no oracle.** For every §9.2 system
     the port can run, `nocc` is k-independent, so `Joint` indices are
     `0..nmo` at every k and `padded_mo_coeff` returns its input **bit-for-bit**
     (`assert_eq!` on the planes). This pins the common case and documents in
     the test itself why the exotic case needs a hand-built fixture.
  4. **The k-dependent fixture from 15-01 Task 4.** Feed the recorded
     `mo_occ` / `mo_energy` and assert `get_nmo(per_kpoint=true)`,
     `get_nocc(per_kpoint=true)`, and both `padding_k_idx` forms against the
     recorded upstream lists. **This is the only test in the phase that
     exercises a non-trivial padding**, so if 15-01 Task 4 could not find a
     natural cell and had to use synthetic `mo_occ`, that is fine and the test
     says so in a comment.
  5. **Frozen variants against the recorded values.** `frozen = 1`,
     `frozen = [0,1]`, and the per-k list form, each checked against 15-01's
     recorded `nocc`/`nmo`/`frozen_mask`. Include the `frozen > max_occ_idx`
     case, which reduces `nmo` but **not** `nocc` — the rule at `:429-435` that
     a `len(frozen)` implementation gets wrong.
  6. **Fractional occupations are refused.** Feed `mo_occ` from a smeared
     `Krhf` run (or a hand-built fractional vector) and assert the error, not a
     number.

  **tests/moref.rs** — the storage-order seam.

  7. **Not a round-trip.** Build a `KScfResult`-shaped `CTensor` whose element
     `(p, i)` is the *distinguishable* value `p + 100·i + 0.5i·j`, with
     `nao ≠ nmo` and both > 1. Convert, then assert `MoCoeff::c` at flat index
     `p*nmo + i` holds exactly that value. A round-trip test passes under a
     double transpose; this does not.
  8. **The seam end to end, against physics.** Run `Krhf` on `he_fcc` 2×2×2 with
     GDF, take `KScfResult.mo_coeff`, convert, and assert
     `Cᴴ S C = I` per k-point to 1e-12 using
     `pyscf_pbc_gto::get_ovlp`. **A transposed `C` fails this**, and it needs no
     upstream. This is the `V j2c Vᴴ = I` trick 14-05 had to invent after the
     fact; write it first this time.
  9. **`mo_slice` boundaries.** `mo_slice(m, 0, nocc)` and
     `mo_slice(m, nocc, nmo)` reassemble to `m` bit-for-bit, and slicing a
     zero-width range is an error rather than an empty success.
