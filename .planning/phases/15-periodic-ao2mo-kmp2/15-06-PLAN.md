**the energy kernel is `raise NotImplementedError` in upstream PySCF 2.12.1**:

```
kump2.py:38-39    def kernel(...):        raise NotImplementedError
kump2.py:384-385  def _add_padding(...):  raise NotImplementedError("Implementation needs to be checked first")
kump2.py:402-403  class KUMP2.kernel(...): raise NotImplementedError
```

RULE 2 makes the Python authoritative. This port ships the same surface and the
same refusal. Inventing a KUMP2 energy here would produce the one number in the
phase that no oracle in the workspace could check.

**`kmp2_stagger.py` (419 l)** — a complete, working finite-size correction:
occupied and virtual orbitals are taken from two *staggered* k-meshes, which
removes the leading finite-size error in the MP2 exchange term. It gets a real
gate.
</objective>

  <name>Task 2: crates/pyscf-pbc-mp/src/kump2.rs — the unrestricted surface</name>

  `padding_k_idx` (:41-103), `padded_mo_energy` (:104-127),
  `padded_mo_coeff` (:128-152), `_is_arraylike` (:153),
  `get_nocc` (:157-260), `get_nmo` (:261-333), `get_frozen_mask` (:334-383).

  Each is the two-spin-channel twin of a 15-03 function. Two rules:

  * **Do not copy 15-03's bodies.** Where the alpha and beta channels are
    genuinely the same computation, call the restricted function twice.
    Where upstream's unrestricted version differs (and it does — `get_nocc`
    at `:157-260` is 100 lines against the restricted 58, because `frozen` may
    be a `(alpha, beta)` pair of any of the four shapes), port the difference
    and say in a comment what it is.
  * `_is_arraylike` (`:153-155`) exists purely to disambiguate those `frozen`
    shapes at runtime. In Rust that disambiguation is the type, so express it as

    ```rust
    pub enum FrozenU { Both(FrozenK), PerSpin(FrozenK, FrozenK) }
    ```

    and note the deviation.

  <name>Task 3: crates/pyscf-pbc-mp/src/kmp2_stagger.rs</name>
  PORT `kernel` (:39-137), `_init_mp_df_eris_stagger` (:140-214), and
  `KMP2_stagger` (:215-360).

  **The construction is most of the work** (`:216-320`), and it has two branches:

  * `flag_submesh = true` (`:232-254`) — two staggered *submeshes* of `mf.kpts`,
    each of half size along every axis. Refuses when any `nks` component is odd
    (`:234-240`). Needs `cell.make_kpts`, `cell.get_abs_kpts`,
    `get_monkhorst_pack_size` — **all shipped**
    (`pyscf_pbc_tools::lattice`, `pyscf-pbc-gto`).
  * `flag_submesh = false` (`:255-278`) — a non-SCF `get_bands` evaluation on a
    shifted mesh of the *same* size, run inside
    `temporary_env(mf, exxdiv='vcut_sph', with_df=FFTDF(...))` (`:270`).
    `Krhf::get_bands` exists (`krhf.rs:106`) and `ExxDiv::VcutSph` is an enum
    variant (`pyscf-pbc-tools/src/coulg.rs:19`) — **but `STATE.md`'s "Phase 11
    deferrals" table lists `exxdiv='vcut_sph'` as
    `NotYetImplemented { phase: 12 }`.** Check whether Phase 12 closed it. If it
    did, port the branch. **If it did not, this branch defers with a
    `NotYetImplemented` naming `vcut_sph` as the blocker, and the `submesh`
    branch still ships and is still gated** — do not substitute `ewald` or
    `None` for `vcut_sph` to make it run, which would silently compute a
    different quantity. Upstream also refuses `cell.dimension < 3` here
    (`:257-265`) with a comment explaining that `get_band` is not accurate for
    lower-dimensional cells; port that refusal.

  The k-index bookkeeping (`:293-318`) maps `kpts_occ`/`kpts_vir` back into
  `self.kpts` via `round_to_fbz(..., wrap_around=True, tol=1e-8)` and a
  `< 1e-10` squared-distance match. `round_to_fbz` is shipped
  (`pyscf_pbc_lib::kpts_helper`) with exactly that signature. **Note the two
  different tolerances** — `1e-8` for the folding and `1e-10` for the match —
  and do not unify them.

  The kernel itself (`:39-137`) is 15-05's loop with `ki`/`kj` running over
  `kpts_idx_occ`, `ka` over `kpts_idx_vir`, `nkpts_ov` in place of `nkpts`, and
  **no SS/OS split** — it accumulates a single `emp2` through
  `woovv = 2·oovv[ika] − oovv[ikb].transpose(0,1,3,2)` (`:132-134`), which is
  the same algebra as 15-05's `edi`/`exi` written as one contraction. Port
  upstream's spelling; do not refactor it into 15-05's.

  Note `:126-127`: `nonzero_vpadding[ka][:nvir]` — the extra `[:nvir]` slice
  that the non-staggered kernel does not have. It is there because the virtual
  padding indices are sized for the full mesh; drop it and the padded case is
  wrong.
</task>

  <name>Task 4: tests</name>

  **crates/pyscf-pbc-mp/tests/kump2.rs**

  1. **The surface works.** On `si` (or any open-shell periodic cell the port
     can converge) with `Kuhf`: `get_nocc(per_kpoint=true)`,
     `get_nmo(per_kpoint=true)` and both `padding_k_idx` forms per spin channel,
     against values recorded from upstream `kump2` in this plan.
  2. **Closed shell reduces to the restricted answer.** On a closed-shell cell,
     the alpha and beta channels give identical `nocc`/`nmo`/padding, and each
     equals 15-03's restricted result **bit-for-bit**. This is the test that
     licenses "call the restricted function twice".
  3. **The refusal is honest.** `KUMP2::kernel` returns
     `NotYetImplemented`, and the test asserts the message names
     `kump2.py:402`. **Add an oracle-gated companion asserting that upstream
     2.12.1 raises `NotImplementedError` at the same call** — so if a future
     PySCF implements it, this port's test goes red and tells us to port it,
     rather than the refusal quietly outliving its reason. This is the same
     device 14-VERIFICATION used to keep the `get_pp` attribution from rotting.
  4. **A `KUMP2` can still be built and inspected** — construction, `nocc`,
     `nmo`, `dump_flags` all succeed on an open-shell cell.

  **crates/pyscf-pbc-mp/tests/kmp2_stagger.rs**

  5. **The odd-mesh refusal, no oracle.** `flag_submesh = true` on a k-mesh with
     an odd component errors with upstream's message (`:236-240`).
  6. **The k-index maps are bijections, no oracle.** `kpts_idx_occ` and
     `kpts_idx_vir` each have exactly `nkpts_ov` **distinct** entries and index
     into `self.kpts` — upstream's own check at `:308-318`, which is worth
     having as a test and not only as a runtime guard.
  7. **The staggered mesh really is staggered, no oracle.** Every
     `kpts_occ − kpts_vir` equals `half_shift` modulo a reciprocal lattice
     vector. This pins the construction with no upstream in the loop.
  8. **The correction has the right sign and size, no oracle.**
     `|e_corr(stagger)| < |e_corr(KMP2)|` at the same mesh on diamond, and the
     gap shrinks as the mesh grows — the finite-size correction's whole purpose.
     Measure the two-point ladder first and gate at what it shows; do not assume
     monotonicity without checking (13-VERIFICATION and 14-VERIFICATION both
     record ladders that plateau or bounce, where a monotone gate would fail a
     correct implementation).
  9. **Oracle, `#[ignore]`d.** `e_corr` against upstream `KMP2_stagger` on
     diamond at `[2,2,2]` with `flag_submesh = true`, both DF routes, at the
     tolerance measured in this plan. Assert `pyscf.__version__ == "2.12.1"`.
  10. **The `flag_submesh = false` branch** — gated if `vcut_sph` is available,
      otherwise a test asserting the deferral names `vcut_sph` as the blocker.
</task>
