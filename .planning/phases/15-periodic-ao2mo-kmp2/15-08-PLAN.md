<objective>
**The phase's largest single speed item, and no earlier plan named it.**

`kmp2.py:98-104` calls `fao2mo = mp._scf.with_df.ao2mo` once per `(ki,ka,kj)`
triple — `nkpts³` times — whenever the mean field is FFTDF or AFTDF. That is the
route the phase's own committed anchor uses (`kmp2.py:820`, `exxdiv=None`,
FFTDF).

Upstream's `fft_ao2mo.general` (`fft_ao2mo.py:102-153`) transforms AO→MO **on
the real-space grid first** —

```python
aos = mydf._numint.eval_ao(cell, coords, kptijkl)                 # :145
mos = [numpy.asarray(lib.dot(c.T, aos[i].T), order='C') ...]      # :147-148
eri = _contract_plain(mydf, mos, coulG, fac, max_memory=...)      # :151
```

— and never materialises the `nao² × nao²` AO block. `aft_ao2mo.general`
(`aft_ao2mo.py:126-…`) has the same shape.

**This port does the opposite** (`crates/pyscf-pbc-df/src/pbc_ao2mo.rs:449-457`):

```rust
pub fn fft_general(df, mos, kptijkl) -> Result<Eri, _> {
    let ao = fft_get_eri(df, kptijkl)?;   // the FULL nao² x nao² AO block
    Ok(mo_eri(&ao, nao, mos))             // then transform_ao_eri
}
```

Consequences, from 15-CONTEXT §7.0/§7.5:

* **flops** `Ng·nao⁴` here against `Ng·(nocc·nvir)²` upstream — a ratio of
  `(nao²/(nocc·nvir))²`. Diamond `gth-szv` (`nao=8, nocc=nvir=4`): **16×**.
  A `gth-dzvp` cell (`nao=26, nocc=4, nvir=22`): **59×**. Times `nkpts³`.
* **memory** `nao⁴` complex per call — 1.6 GB at `nao = 100`, on a machine
  where 17-12's host suite already exit-137s (`STATE.md`) and where the
  standing note `materialised-grid-values-oom` records the same failure mode.
* **RULE 2** — an unrecorded structural deviation from upstream, shipped by
  plan 14-05. Phase 15 is the first caller that runs it `nkpts³` times, so
  Phase 15 is where it gets fixed and recorded.

This plan depends on nothing else in the phase and **starts at wave 0**, beside
15-01 and 15-02.

**Non-goal:** changing any number. Every gate that exists today must stay at its
current value, and the AO-ERI route is not deleted — `get_eri` and
`ao2mo_7d`'s AO-block callers still need it.
</objective>

  <name>Task 1: read both sides before writing anything</name>
  `sed -n '95,200p' pyscf/pbc/df/fft_ao2mo.py` — `general`, `_contract_plain`
  and `_contract_compact`. Note exactly three things and write them down:

  1. **What is transformed and when.** `mos[i] = C_iᵀ · AO(k_i)ᵀ` is an
     `(nmo_i, ngrids)` array; the AO axis is gone before any FFT happens.
  2. **What `_contract_plain` actually contracts** — the bra MO-pair density
     `mo_pairs[i,j](r) = conj(mos[0][i,r])·mos[1][j,r]` is FFT'd, multiplied by
     `coulG·fac`, and inverse-transformed against the ket pair. The conjugation
     pattern must match `df_ao2mo`'s module docs (bra conjugated, ket not);
     confirm it against this port's `fft_ao_pairs_g`/`contract_eri`, which
     already encode the AO-level version of the same convention.
  3. **The gamma-point + all-real shortcut** (`:126-143`) and the `iden_coeffs`
     compact branch. KMP2 never reaches the compact branch (its four MO blocks
     are `orbo/orbv/orbo/orbv` and are never identical), so **it is out of scope
     here**; say so rather than porting an untestable path.

  Then read `pbc_ao2mo.rs` in full — `fft_ao_pairs_g` (`:103`),
  `fft_get_eri` (`:231`), `transform_ao_eri` (`:288`), `fft_general` (`:449`) —
  and `crates/pyscf-pbc-gto`'s `eval_ao_kpts`, which is where the real-space AO
  values come from.
</task>

<task type="auto">
  <name>Task 2: the per-`q` cache (15-CONTEXT §7.6)</name>
  `fft_get_eri` (`:246-262`) recomputes `get_gv_weights`, `get_gv` and
  `get_coulG` on **every call**. Inside `KMP2` that is `nkpts³` rebuilds of
  three quantities that depend only on `q = k_j − k_i`, of which there are at
  most `nkpts` distinct values.

  Add a small, explicit, caller-owned cache — not a hidden memo inside the
  builder:

  ```rust
  /// `(Gv, weights, coulG·weights)` at one momentum transfer `q`.
  pub struct CoulGCache { /* … */ }
  impl CoulGCache {
      pub fn build(cell: &Cell, mesh: [usize; 3], q: [f64; 3]) -> Result<Self, PbcDfError>;
  }
  ```

  `fft_general` / `aft_general` / `fft_get_eri` / `aft_get_eri` gain
  `*_with_cache(..., &CoulGCache)` siblings; the existing signatures keep
  working by building a cache on the spot, so **no current caller changes**.
  15-05 builds one table of `nkpts` caches before its loop.

  Prove it changes nothing: Task 5 test 1 asserts the cached and uncached forms
  are **bit-identical** on the anchor cell.
</task>

<task type="auto">
  <name>Task 3: the MO-first path</name>
  Add to `pbc_ao2mo.rs`:

  ```rust
  /// `fft_ao2mo.general`'s ACTUAL route (fft_ao2mo.py:145-152): transform to
  /// MOs on the real-space grid, then contract MO-pair densities through
  /// `coulG`. Cost `Ng·(n1·n2 + n3·n4)` against `fft_general`'s `Ng·nao⁴`.
  pub fn fft_general_mo_first(
      df: &Fftdf, mos: [&MoCoeff; 4], kptijkl: [[f64; 3]; 4],
      cache: Option<&CoulGCache>,
  ) -> Result<Eri, PbcDfError>;

  pub fn aft_general_mo_first(/* … */) -> Result<Eri, PbcDfError>;
  ```

  Structure, following upstream line for line:

  * `eval_ao_kpts` at the four k-points once (`:145`).
  * `mos[i][m, r] = Σ_p C_i[p, m] · AO_i[r, p]` — `(nmo_i, ngrids)`, four of
    them (`:147-148`). This is the only place the `nao` axis appears.
  * `fac[r] = exp(-i·q·r)` (`:149`), `q = k_j − k_i`.
  * Bra pair density on the grid, FFT, multiply by `coulG·weights·fac`, then
    contract against the ket pair — the same three steps `fft_ao_pairs_g` +
    `contract_eri` already perform at the AO level. **Reuse them if their MO
    generalisation is a change of dimension only; write new code only where the
    shapes genuinely differ, and say which in the summary.**
  * The gamma-point/all-real shortcut (`:126-143`) is **out of scope** (Task 1.3)
    — the general complex path is correct there too, just slower, and KMP2 never
    takes the shortcut. Record the omission as a `DEVIATION:` comment naming the
    upstream lines, not as a silent gap.

  **Blocking.** Upstream blocks the pair loop against `max_memory`
  (`_contract_plain`'s `blksize`). Port that: the intermediate is
  `(npair_block, ngrids)`, and an unblocked version is
  `(nocc·nvir)·Ng` complex, which is the same OOM class this plan exists to
  remove. Reuse `pyscf-ccsd`'s `PYSCF_MAX_MEMORY` budget, as 15-05 does.

  **Reductions.** The contraction over `G` is `Ng`-long and is exactly what
  D-PBC-17 governs. Ordered dot only, and it is `oracle_zdotu` — the bra is
  already conjugated by the pair-density construction, so a second conjugation
  from `oracle_zdot` would be wrong (15-CONTEXT §3.10). **No `zgemm_dense`**
  (§7.3). Parallelise with `rayon` over disjoint output rows (bra pairs).

  Leave `fft_general` / `aft_general` in place and unchanged — `get_eri` and the
  AO-block consumers still need `fft_get_eri`, and Task 5 test 2 needs both
  routes reachable to compare them.
</task>
