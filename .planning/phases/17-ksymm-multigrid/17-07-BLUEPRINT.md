### The one design consequence to settle first

`kpts()` returns a **borrowed slice** `&[[f64; 3]]`. So your adapter must **own a
`Vec<[f64; 3]>` holding the IBZ points** and return a reference to it. Store the
`KPoints` and a materialised `kpts_ibz: Vec<[f64; 3]>` side by side in the
struct. Everything downstream — `nkpts`, the `idx(set, k) = set * nkpts + k`
layout in `KScfResult`, DIIS's `KFockSubspace` — then operates on IBZ indices
with no change anywhere else. That is the entire mechanism.

## 2. What the trait's own docs already commit you to

Two of the plan's traps are already written into `khooks.rs`, which means the
driver assumes them and you inherit the obligation:

* `get_occ`'s doc: *"Assign occupations with ONE Fermi level per spin channel
  **across the whole Brillouin zone**."* This is 17-CONTEXT §3.4 stated at the
  trait level — your impl must unfold `mo_energy` to the full BZ, sort THAT,
  take `fermi = mo_energy[nocc - 1]` with `nocc = tot_electrons(kpts.nkpts)/2`,
  then fold back via `check_mo_occ_symmetry`. Do not fuse the unfold into the
  IBZ loop.
* `eig`'s doc: returns `(mo_energy, mo_coeff)` indexed `set * nkpts + k`, with
  `mo_coeff` **COLUMN-MAJOR**. 17-04's `symm_orb` is column-major too, so the
  `use_ao_symmetry` branch's block-diagonalisation composes without a transpose
  — but that is exactly the shape of the 14-05 defect (+6 306 866.73 Ha), so
  assert it rather than assuming it.

## 5. Hard-won lessons from this phase — apply, do not rediscover

1. **Tolerances are JOINTLY limited by `cell.precision` AND `conv_tol_grad`.**
   Read `17-04-MEASUREMENT.md`. At the defaults (1e-8/1e-8) a symmetry residual
   against a converged SCF floors at ~4e-10; at 1e-10/1e-10 it reaches ~5e-13.
   `pyscf_pbc_gto::test_systems` now has `si_precision(f64)` /
   `diamond_precision(f64)` for tight fixtures (added by 17-04). Mutating
   `cell.precision` on an already-built cell and calling the `build()` **method**
   silently drops the pseudopotential (`Nocc (112) > Nmo (64)`) — go through
   `Cell::build(CellBuildArgs { .., precision, .. })`.
2. **Assert on the MAXIMUM residual over all k and all index pairs, and print it
   under `--nocapture`** — never the first violation. 17-04's first-violation
   assert reported 1.58e-11 while the true max was 3.99e-10, which materially
   confused the diagnosis.
3. **Pin `cell.mesh` on both sides of every two-run comparison** (§3.3) —
   turning on `space_group_symmetry` can itself change the mesh via
   `check_mesh_symmetry`, so an unpinned A-vs-B test measures the mesh change,
   not the symmetry.
4. **Name the DF route in every upstream comparison** (Gate D). 15-CONTEXT §2:
   an unqualified "matches upstream" is untestable. Report FFTDF and GDF rows
   separately.
5. **A "faster" route must be measured, not assumed.** `zgemm_dense` lost 6-12x
   to a host rayon loop; 17-01 measured upstream's own multigrid SLOWER than its
   reference numint (0.18-0.49x); 17-05 measured the plan's predicted star-search
   parallelism at 0.99x and had to find the real hotspot elsewhere. If Task 6's
   fast `get_jk` path measures slower, record it and ship only the reference
   route.

## 6. Environment

Sessions restart every ~20-40 min and kill background agents. The plans that
completed (17-05, 17-06) did so by: landing each task on disk as a compiling
unit before starting the next; writing the SUMMARY **incrementally** from the
first task, not at the end; using **foreground** Bash with long timeouts
(`run_in_background` + monitor polling has stalled every time it was tried here);
and running tests in `--release` on `[2,2,2]` while iterating.

Two live hazards: a sibling `libxc_rs` workspace is sometimes regenerated
concurrently, producing transient `failed to get libxc-rkernel-*` cargo errors
(re-run, do not "fix"); and running a full test binary with default parallelism
can OOM this box — `--test-threads=1` for anything heavy.
