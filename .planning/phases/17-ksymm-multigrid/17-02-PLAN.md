<objective>
The bottom of the symmetry stack: detect the lattice's rotations, classify the
crystal, and give the point group an algebraic structure (multiplication table,
conjugacy classes, character table) that `space_group.py` and `basis.py` will
both read.

Port `pyscf/pbc/symm/geom.py` (245 l), `tables.py` (100 l) and `group.py`
(476 l). All three are pure integer/float lattice algebra with **no** cintx, no
grids and no cubecl — the cheapest wave in the phase and the one everything else
sits on.

**This plan also records D-PBC-25** (17-CONTEXT §4), the crate-layering ruling,
because plan 17-05 cannot be written until it is settled.
</objective>

<task type="tdd">
  <name>Task 1: geom.rs — search_point_group_ops</name>
  `geom.py:27-77`. Brute force over `lib.cartesian_prod([[1,0,-1]]*9)` —
  19 683 candidate integer `3×3` matrices `W`, kept when `Wᵀ G W` preserves the
  metric `G = a aᵀ`.

  **Three things that are load-bearing and easy to lose:**

  1. **Iteration order.** `cartesian_prod` varies the LAST axis fastest, and
     survivors are appended in that order. The order is observable through
     `stars_ops` and `finger(kpts_ibz)` (17-CONTEXT §3.6). Reproduce it exactly;
     a `HashSet` anywhere in this function is a defect.
  2. **The clip.** `geom.py:38-41` and `:57-59` do
     `ratio = np.clip(G/outer(n,n), -1., 1.)` before `arccos`, with the pre-fix
     line kept as a comment citing upstream issue 3113. On a cubic lattice the
     diagonal exceeds 1 by rounding, unclipped `arccos` gives NaN, the `>`
     comparison then silently fails, and a **wrong rotation is admitted**. Port
     the clip and cite the issue in the doc comment.
  3. **The low-dimension filters** (`:65-72`): reject any `W` that inverts a
     non-periodic axis, or that swaps a periodic and a non-periodic axis. These
     are the only reason `graphene` (`dimension = 2`) works.

  Tolerance: `SYMPREC = 1e-6` (`geom.py:25`), **in units of length**, and the
  angle test compares `sin(Δangle)² · (n+ñ)²/4` against `tol²` — not the angle
  itself. Port the expression, not a paraphrase.

  Tests (`tests/geom.rs`):
  * fcc `si` → 48 rotations; simple cubic → 48; the `graphene` slab → 24
    (measure the true counts in Task 1's own exploration and pin them).
  * every returned `W` satisfies `Wᵀ G W == G` to 1e-12 and `|det W| == 1`.
  * the set is closed under multiplication and inverse — that is the definition
    of a group and it needs no oracle.
  * a deliberately distorted lattice (one vector scaled by `1 + 2·SYMPREC`)
    returns strictly fewer ops.
</task>

  <name>Task 2: geom.rs — search_space_group_ops and get_crystal_class</name>
  `geom.py:79-147` and `:149-245`. For each rotation, find the fractional
  translations that map the atom set onto itself (`search_space_group_ops`), then
  classify (`get_crystal_class`).

  The translation search compares **scaled** atom coordinates modulo 1 and must
  respect atom *type* — two atoms of different elements are never interchanged.
  Upstream also encodes the ghost-atom refusal in the spglib bridge
  (`pyscf_spglib.py:36-38`); the native path should refuse ghosts the same way
  rather than silently mapping them.

  Tests: `si`/`diamond` (fcc, 2 atoms, **non-symmorphic** — the diamond glide is
  the whole reason `symmorphic` is a separate flag), `lif` (rocksalt,
  symmorphic), `he_fcc` (one atom, symmorphic), `graphene`. Assert the crystal
  class string against upstream for each.
</task>

<task type="tdd">
  <name>Task 4: group.rs — PGElement and FiniteGroup</name>
  `group.py:29-397`. `GroupElement` (abstract), `PGElement` (a `3×3` integer
  matrix with a hash), `FiniteGroup` with lazily-built `hash_table`,
  `inverse_table`, `multiplication_table`, `conjugacy_table`,
  `conjugacy_classes` and `character_table`.

  Rust notes:
  * `PGElement.__hash__` (`group.py:80-92`) encodes the matrix into an integer,
    and `decrypt_hash` (`:94-115`) reverses it. That encoding is the group's
    identity and its ordering (`__lt__`, `:117`). Port the encoding exactly —
    a different-but-valid hash changes element order and therefore changes
    `character_table` row order, which `basis.py` reads by index.
  * `character_table` (`:313-360`) does Burnside/eigenvector work over the class
    algebra. It is the only numerically delicate function in the file; give it
    the `_round_zero(a, tol=1e-9)` (`:25`) upstream uses.
  * `FiniteGroup.__and__`/`__or__`/`issubset` (`:173-201`) are set ops on
    elements; used by `little_cogroups` in 17-05.

  Tests (`tests/group.rs`), all oracle-free:
  * group axioms on `si`'s 48-element point group: closure, associativity on a
    random sample, identity, inverses.
  * `multiplication_table` is a Latin square.
  * `Σ_classes |class| · |χ_ir|² == |G|` for every irrep, and orthogonality of
    the character table rows — these two pin `character_table` without upstream.
  * `PointGroup::group_name` for `si`, `diamond`, `lif`, `he_fcc`, `graphene`
    against the strings upstream prints.
</task>
