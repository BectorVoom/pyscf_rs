<task type="tdd">
  <name>Task 1: the grid-level task list</name>
  `multigrid.py`'s `multi_grids_tasks_for_rcut` / `multi_grids_tasks_for_ke_cut`
  and `_primitive_gto_cutoff`. Pure host logic: sort primitives by exponent into
  `n` levels, give each level a mesh and an `rcut`, and emit the shell-pair task
  list.

  This is where multigrid's accuracy is *decided* — a primitive assigned to too
  coarse a level is the entire error budget. Gate the assignment itself, not
  only the final energy: for each reference cell, assert the level counts and
  the per-level mesh against upstream's, so a Gate-E failure can be localised to
  "wrong task list" vs "wrong kernel" without a bisect.

  Note this is a **different** compact/smooth split from `_RangeSeparatedCell`
  (plan 17-10): multigrid classifies by exponent into `n` levels, the RS cell
  into compact/smooth/local by two thresholds. They share no code and must not
  be unified.
</task>

<task type="tdd">
  <name>Task 2: the collocation kernel (NUMINT_fill)</name>
  `multigrid.py:146` — `libdft.NUMINT_fill2c`. Evaluate a shell pair's product
  Gaussian on a level's uniform mesh and accumulate into the density or the
  potential-weighted matrix.

  Kernel-level tests in `crates/pyscf-kernels/tests/`, against an independent
  host reference and **never** against the kernel itself:
  * a single s-type Gaussian on a fine mesh integrates to its analytic norm to
    1e-12;
  * for `l = 0…4`, the collocated product on a fine mesh matches a direct
    `eval_gto` product to 1e-12;
  * the periodic image wrap is exact — a Gaussian centred at a cell corner gives
    the same total as one centred at the middle.

  Grid-point accumulation is a D-PBC-17 shape: `oracle_sum` ordering, with the
  `RAYON_NUM_THREADS` 1-vs-8 bit-identity test from the first version.
</task>

<task type="tdd">
  <name>Task 3: the density driver (NUMINT_rho_drv)</name>
  `multigrid.py:280` — `libdft.NUMINT_rho_drv`. Contract the density matrix with
  collocated pairs to produce `rho` on each level, then combine levels through
  the G-space filter.

  The inter-level combination is an FFT-domain operation and needs no new FFT:
  `pyscf-pbc-tools::fft`/`ifft` (`fft.rs:96, 110`) already ship.
  `multigrid.py:457` also calls `ft_ao.ft_ao` for the analytic G-space half —
  that is the single-centre `ft_ao` plan 13-01 already shipped
  (`crates/pyscf-pbc-df/src/ft_ao/single.rs`). Reuse both; port neither.

  Test: `∫ rho dr == nelectron` to 1e-10 on every reference cell, at every level
  count. That one assertion catches a wrong level weight, a wrong mesh volume
  factor and a dropped level.
</task>
