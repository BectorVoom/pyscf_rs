<objective>
`pyscf/pbc/lib/kpts.py` (1223 l) — the largest single file in the phase and the
one every `*_ksymm` adapter talks to. It folds the full BZ into an irreducible
wedge, records how to unfold each quantity, and hands the SCF a weight per IBZ
point.

**It does not go where its file name says.** D-PBC-25 (recorded by 17-02) puts
`KPoints` in `pyscf-pbc-symm`, because upstream declares
`class KPoints(symm.Symmetry, lib.StreamObject)` (`kpts.py:847`) and mirroring
`lib/kpts.py` into `pyscf-pbc-lib` is a dependency cycle — that crate sits below
`pyscf-pbc-symm` and cannot see `Cell` at all.

This plan also closes the oldest Phase-17 promise in the tree:
`crates/pyscf-pbc-gto/src/kpts_mesh.rs:112-121`, which has refused
`space_group_symmetry` with `NotYetImplemented { phase: 17 }` since plan 09-07.
</objective>

<task type="tdd">
  <name>Task 1: the fold — make_kpts_ibz and map_k_points_fast</name>
  `kpts.py:40-115` (`make_kpts_ibz`) and `:307-331` (`map_k_points_fast`).
  Produce `kpts_ibz`, `ibz2bz`, `bz2ibz`, `weights_ibz`, `stars`, `stars_ops`,
  `stars_ops_bz`, `nkpts_ibz`.

  **Gate A is this task's test and it needs no oracle beyond six integers**
  (17-CONTEXT §2.2, confirmed by 17-01 Task 1). On upstream's Si cell at
  `[16,16,16]`: **145 / 145 / 245 / 408 / 816 / 2052** across the six
  configurations. These are *exact integers*. A wrong symmorphic branch, a wrong
  time-reversal fold or a wrong `wrap_around` interaction moves one of them.

  Additional oracle-free invariants, all cheap and all catching different bugs:
  * `Σ weights_ibz == 1` to 1e-15, and `weights_ibz[i] == |stars[i]| / nkpts`.
  * `bz2ibz` is total and `ibz2bz[bz2ibz[k]]` lands in `k`'s own star.
  * every `k` in `stars[i]` satisfies `stars_ops[i][j] · kpts_ibz[i] ≡ k`
    modulo a reciprocal vector, to `KPT_DIFF_TOL`.
  * `stars_ops[i][j] == stars_ops_bz[stars[i][j]]` — upstream's own consistency
    check (`test_kpts_ksymm.py:60-65`), which it writes as a loop because it has
    caught a real bug.

  Reuse, do not re-port: `round_to_fbz`, `member`, `unique`, `KPT_DIFF_TOL`
  from `pyscf-pbc-lib/src/kpts_helper.rs:28-224`.

  **Speed:** the star search is `O(nkpts × nop)` and each BZ k-point's star
  membership is independent of every other's — a `rayon::par_iter` over the
  outer BZ loop is safe with no accumulation ordering to protect (unlike
  Task 4's density sum). Do it; at `nkpts = 4096` (Si `[16,16,16]`, Gate A)
  this is the difference between a fixture that runs in the test suite and one
  that does not.
</task>

<task type="tdd">
  <name>Task 2: is_trim, and time-reversal</name>
  `kpts_helper.py:39` — `is_trim(cell, kpts, tol)`, the time-reversal-invariant
  momenta. It is **missing** from `crates/pyscf-pbc-lib/src/kpts_helper.rs` and
  `khf_ksymm.py:126` needs it for the `eig_trs` branch. It is one function; it
  lands in `pyscf-pbc-lib` next to its siblings.

  Time-reversal folding is what takes Si `[16,16,16]` from 245 to 145 IBZ points
  and, with no space group at all, from 4096 to 2052. `2052 = 4096/2 + 4`
  independently pins the TRIM count at 4 — assert that decomposition explicitly,
  because it separates "the fold works" from "the TRIM set is right".
</task>

<task type="tdd">
  <name>Task 3: the unfolds — transform_*</name>
  `kpts.py:449-716`: `transform_mo_coeff` (`:449`), `transform_mo_coeff_k`
  (`:494`), `transform_mo_occ` (`:528`), `transform_dm` (`:556`),
  `dm_at_ref_cell` (`:622`), `transform_mo_energy` (`:644`),
  `transform_1e_operator` (`:663`), `check_mo_occ_symmetry` (`:717`),
  `get_rotation_mat_for_mos` (`:757`).

  Each delegates the per-op work to `symmetry.rs`'s transforms from 17-03; this
  layer is the loop over stars plus the phase bookkeeping.

  **Gate B is this task's test** (17-CONTEXT §2.2), against **one** converged
  full-BZ `KRKS` at `conv_tol = 1e-11` — never two SCFs, because then the
  residual is convergence noise, not algebra:

  ```
  transform_dm(dm[ibz2bz])           vs  dm            → 17-01 Task 2's number
  transform_1e_operator(fock[ibz2bz]) vs fock
  transform_mo_occ / transform_mo_energy
  make_rdm1(transform_mo_coeff(...)) vs dm
  ```

  **17-CONTEXT §3.1: never compare `mo_coeff` elementwise.** It is defined only
  up to a unitary within each degenerate subspace, and every symmetric cell has
  degeneracies. Upstream's own test builds a DM and compares that
  (`test_kpts_ksymm.py:96-99`). Add a test that asserts the elementwise
  comparison *fails*, citing §3.1, so nobody "tightens" the DM comparison into
  an MO one later.

  `MORotationMatrix` (`kpts.py:1127-1173`) caches
  `get_rotation_mat_for_mos`; port it as a lazily-built struct, since
  `kmp2_ksymm` and `kccsd_rhf_ksymm` both read it per k-tuple.

  **Speed:** each of these unfolds one star at a time into an independent slot
  of the BZ-length output array. Parallelise the outer star loop with rayon —
  the write targets are disjoint by construction (each BZ k-point belongs to
  exactly one star), so no `oracle_sum`-style reduction is needed here, only a
  `RAYON_NUM_THREADS` 1-vs-8 bit-identity test proving the disjointness holds
  in code, not just on paper.
</task>

<task type="tdd">
  <name>Task 4: symmetrize_density / symmetrize_wavefunction — a D-PBC-17 site</name>
  `kpts.py:377-448`. Real-space density symmetrisation on the FFT mesh: rotate
  each grid point's index under every star op and accumulate.

  **17-CONTEXT §3.8:** this is an `nkpts × ngrids` accumulation, the same shape
  D-PBC-17 governs and that 15-CONTEXT ruled on for KMP2. It goes through
  `oracle_sum`/`oracle_zsum` **in the first version, not as a retrofit**, and
  ships with the §9.3 bit-identity test at `RAYON_NUM_THREADS` 1 and 8 from day
  one. Retrofitting determinism has cost this project time before; do not.

  The grid-index rotation is integer arithmetic on the mesh and must land
  exactly on a mesh point — that is precisely what `check_mesh_symmetry`
  (17-03 Task 4) guarantees. **Assert it**: if a rotated index misses, fail
  loudly rather than rounding, because a silent round is a wrong density.

  Test: upstream's `test_kpts_ksymm.py:132-143` — accumulate `get_rho` over the
  IBZ with `symmetrize_density` and compare to the full-BZ `get_rho`. Upstream
  asserts 8 decimals against a `max_cycle=1` reference; use 17-01 Task 2's
  measured floor.
</task>
