# Quick Task 260529-i2x: Refactor gemm.rs to a cubecl generic-float kernel + ROCm random-oracle test

## Task

Refactor `crates/pyscf-algebra/src/gemm.rs` from its Phase-1 `NotYetImplemented`
stub into a real cubecl GEMM kernel generic over the float element type
(`F: Float`), and validate it with a **randomized oracle differential test**
executed on the **ROCm** backend (`cubecl_hip::HipRuntime`, device `gfx1152`).

## Key constraints discovered (research, this session)

1. **`Tensor<T>` has no device allocator yet** — `id = BufferId(u64::MAX)` is a
   Phase-1 sentinel, never dereferenced. The public `gemm(&AlgebraClient,
   &Tensor, &Tensor, &mut Tensor)` therefore *cannot* read device data until the
   Phase-2 allocator lands. `backend_matrix.rs` asserts `gemm(...)` returns
   `NotYetImplemented`. → **Keep the `Tensor`-based `gemm()` stub unchanged**;
   the real kernel is exercised through a host-slice launcher.
2. **Oracle ground truth already exists**: `oracle::oracle_einsum("ij,jk->ik",
   a, (m,k), b, (k,n))` is a bit-deterministic CPU GEMM — the differential
   reference for the random-oracle test.
3. **Algebra-wall (ALG-06)**: cubecl types stay inside `pyscf-algebra`. Public
   dispatch fn bounds on the existing `DeviceScalar` abstraction; the cubecl
   `Runtime` generic stays internal (matched off `AlgebraClient`, mirroring
   `select::construct_client`).
4. **libxc stays 0** in `pyscf-algebra --features rocm` (verified) — building
   the rocm test does NOT trigger the ~6h libxc compile. Build scoped to
   `-p pyscf-algebra` only.
5. cubecl `0.10.0`; `ComputeClient<R>` is single-type-param; ROCm client =
   `cubecl_hip::HipRuntime::client(&cubecl_hip::AmdDevice::default())`.

## Tasks

### T1 — Generic cubecl GEMM kernel + backend-dispatched launcher (`gemm.rs`)
- `#[cube(launch)] fn gemm_kernel<F: Float>(lhs, rhs, out: &Array<F>, m,k,n: u32)`:
  one thread per output element (ABSOLUTE_POS), bounds-guarded, runtime k-loop.
- `fn launch_gemm<R: Runtime, F: DeviceScalar>(client, lhs, rhs, m,k,n) -> Vec<F>`
  (private): upload, launch `groups×256` threads, read back.
- `pub fn gemm_dense<F: DeviceScalar>(client: &AlgebraClient, lhs, rhs, m,k,n)
  -> Result<Vec<F>, AlgebraError>`: validates shapes, matches `AlgebraClient`
  arm → `launch_gemm::<Runtime, F>` (Cpu always; Rocm/Cuda/Wgpu cfg-gated).
- Extend `DeviceScalar` (scalar.rs) supertraits with `CubeElement + bytemuck::Pod`
  (f32/f64 already satisfy) so the public bound stays `F: DeviceScalar`.
- Re-export `gemm_dense` from lib.rs. Leave `gemm()` stub + doc-note.
- **verify:** `cargo build -p pyscf-algebra --tests` (cpu) clean.
- **done:** kernel + launcher compile; public surface wall-clean.

### T2 — Randomized oracle differential test (`tests/gemm_oracle.rs`)
- Deterministic LCG random matrices (reproducible per test-guideline).
- CPU path (default features, always runs): `gemm_dense::<f64>` vs
  `oracle_einsum` over several random shapes; max-abs-diff < 1e-8.
- ROCm path (`#[cfg(feature = "rocm")]`): same, asserting the resolved backend
  is actually `BackendKind::Rocm` (not a cpu fallback), running on `gfx1152`.
- **verify:** `cargo test -p pyscf-algebra` (cpu) green;
  `cargo test -p pyscf-algebra --features rocm gemm_oracle` green on ROCm.
- **done:** device GEMM matches CPU oracle within tol on real ROCm hardware.

## Out of scope
- Wiring the `Tensor`-based `gemm()` (blocked on Phase-2 allocator).
- Tiled/shared-memory optimization — naive kernel is sufficient for the oracle
  correctness gate.

## must_haves
- truths: device GEMM on ROCm matches the deterministic CPU oracle within 1e-8.
- artifacts: `gemm_kernel`/`gemm_dense` in gemm.rs; `tests/gemm_oracle.rs`.
- key_links: gemm.rs, scalar.rs, lib.rs, oracle.rs, tests/gemm_oracle.rs.
