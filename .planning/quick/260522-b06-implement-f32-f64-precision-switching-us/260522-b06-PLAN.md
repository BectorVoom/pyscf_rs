<objective>
Make pyscf-rs generic over floating-point precision (f32 / f64) using Rust
generics, threaded bottom-up through the active compute crates. f64 stays the
default type parameter everywhere, so existing bit-exact oracle/regression
tests compile and run unchanged; f32 is an explicit opt-in for speed / GPU.

Purpose: enable a single-source f32 path without forking algorithms, while
honoring the algebra-wall (only pyscf-algebra / pyscf-runtime / pyscf-kernels
may name cubecl) and avoiding workspace-wide f32 monomorphization blowup.

Output:
- A host-only `Scalar` trait in pyscf-core (the cubecl-free leaf), with a
  `T -> DType` reconciliation const.
- A `DeviceScalar` sealed extension trait in pyscf-algebra/pyscf-kernels that
  adds the `cubecl::Float` device bound ONLY inside the wall.
- A generic `Tensor<T = f64>` carrying both the compile-time element type and
  the runtime `DType` tag.
- Method crates (gto/scf/df/diis) consuming the generic surface via the f64
  default, so their f64 control plane (conv_tol, mo_energy, energies) is
  untouched.
- One narrow f32 smoke test proving the generic path instantiates at f32.

TRADE-OFF (explicit): f32 CANNOT satisfy bit-exact PySCF parity. f32 is a
speed/GPU path only. All oracle/parity regression tests stay on f64 (the
default) and are not retargeted to f32.
</objective>
