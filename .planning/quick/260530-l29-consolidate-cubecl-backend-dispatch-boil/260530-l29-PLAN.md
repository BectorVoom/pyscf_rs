<objective>
Eliminate the repeated cfg-gated 4-arm `match client { AlgebraClient::Cpu(c) => launch_X::<CpuRuntime, F>(c, ...), #[cfg] Cuda => CudaRuntime, #[cfg] Wgpu => WgpuRuntime, #[cfg] Rocm => HipRuntime }` boilerplate that recurs **16 times** across 8 files in `pyscf-algebra`, replacing each with a single `dispatch_backend!` macro invocation. The cfg-gated arms are written ONCE, in a new `dispatch.rs`.

Purpose: This is a MECHANICAL, BEHAVIOR-PRESERVING dedup. No kernel logic changes, no numerical changes, no manual-conformance pass, no performance rewrite. The win is that adding/removing a backend (or fixing a per-backend bug) edits one site instead of sixteen, and the ALG-06 "Runtime generic stays inside the wall" contract is centralized in one auditable macro.

Output:
- `crates/pyscf-algebra/src/dispatch.rs` — the `dispatch_backend!` macro (single source of the 4 cfg-gated arms).
- 7 engine files (`gemm`, `gemv`, `dot`, `axpy`, `scal`, `transpose`, `reduce`) + `device_buffer.rs` rewritten to call the macro.
- `lib.rs` — declares the new `dispatch` module.

Scope note (per task_intent + constraints): ONLY `pyscf-algebra` is in scope.
- `pyscf-kernels/src/eval_gto.rs` is OUT OF SCOPE. It does NOT use the per-`Runtime` `match client { AlgebraClient::Cpu(c) => ... }` shape at all — it dispatches on `client.kind()` against a single `BackendKind::Cpu` guard plus a `tracing::warn!` CPU fallback (no cubecl `Runtime` token is ever selected per-arm). Forcing the macro there would be a shared abstraction over genuinely different shapes.
- `pyscf-dft/src/numint.rs` is OUT OF SCOPE. Its matches are on `self.dtype` (`DType::F64`/`F32`) and `self.backend` (an XC-backend abstraction), a different dispatch axis from the `AlgebraClient` enum-of-cubecl-clients. The macro does not apply.
</objective>

Design the macro to cover BOTH call-site shapes observed across the 16 sites (see `<interfaces>`):
  1. A `$client:expr` to match on (always an `&AlgebraClient`).
  2. A binding `$c:ident` for the inner `ComputeClient` of the matched arm.
  3. A Runtime-type binding `$rt:ident` (or `$rt:ty` positioned as a macro metavariable) that each arm substitutes with the concrete cubecl Runtime type for that backend.
  4. A `$body:expr` (or `$body:block`) that is expanded ONCE PER ARM, referencing `$c` and `$rt`.

The macro expands to a `match $client { ... }` EXPRESSION so it serves the value-returning sites (`let out = dispatch_backend!(...);`) AND the statement sites (`dispatch_backend!(...);`) identically. Each arm MUST carry the SAME cfg attribute as the corresponding `AlgebraClient` variant:
  - `AlgebraClient::Cpu($c) => { /* $rt = cubecl_cpu::CpuRuntime */ $body }`
  - `#[cfg(feature = "cuda")] AlgebraClient::Cuda($c) => { /* $rt = cubecl_cuda::CudaRuntime */ $body }`
  - `#[cfg(feature = "wgpu")] AlgebraClient::Wgpu($c) => { /* $rt = cubecl_wgpu::WgpuRuntime */ $body }`
  - `#[cfg(feature = "rocm")] AlgebraClient::Rocm($c) => { /* $rt = cubecl_hip::HipRuntime */ $body }`

Implementation guidance for binding the per-arm Runtime type: introduce a type alias inside each arm so the body can name `$rt` uniformly, e.g. each arm opens with a local `type $rt = <concrete Runtime>;` then runs `$body`. This lets a single `$body` token tree containing `launch_gemm::<$rt, F>(...)` expand correctly in all 4 arms (each arm's local `type $rt = ...;` resolves it to that backend's Runtime). This is the cleanest way to let ONE body serve every arm with the Runtime token varying per arm. Verify this `type`-alias-per-arm approach compiles; if the `type` alias collides with hygiene, fall back to passing the Runtime type positionally and emitting one arm per concrete type via internal macro recursion — but prefer the type-alias form first as it keeps the macro readable.

Put a doc comment on the macro stating: this is the SINGLE cfg-gated AlgebraClient fanout (replaces 16 hand-written matches); it preserves the ALG-06 wall because the Runtime type never escapes the expansion; adding a backend means adding ONE arm here. Do NOT add any new cubecl imports beyond what the arms reference by fully-qualified path (`cubecl_cpu::CpuRuntime` etc., already crate deps).

In `crates/pyscf-algebra/src/lib.rs`: add `#[macro_use] mod dispatch;` (or `mod dispatch;` plus `pub(crate) use` if `#[macro_use]` is undesired) positioned BEFORE the engine modules (`axpy`, `dot`, `gemm`, ... ) so the macro is in scope for them. The macro is crate-internal — do NOT `pub use` it (no public API change). Keep all existing `pub use` re-exports unchanged.

Do NOT modify any engine file in this task — Task 1 only lands the macro + module declaration. The crate must still build because the existing hand-written matches are untouched and the new macro is simply unused-but-defined (a `macro_rules!` that is defined-and-unused does not warn).
