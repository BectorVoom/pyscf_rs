# Phase quick-260530-l29 Plan 01: Consolidate cubecl backend dispatch boilerplate Summary

One-liner: Replaced 16 hand-written cfg-gated 4-arm `match client { AlgebraClient::Cpu(c) => launch_X::<CpuRuntime, F>(c, …), … }` blocks across 8 pyscf-algebra files with a single `dispatch_backend!` macro, the lone place the cubecl `Runtime` type is now selected (ALG-06 wall centralized), netting -154 lines.

## What was built

- **`dispatch.rs`** — `macro_rules! dispatch_backend`, the SINGLE cfg-gated `AlgebraClient` fanout. It expands to a `match $client { … }` expression so it serves both value-returning sites (`let out = dispatch_backend!(…)`) and statement sites (`dispatch_backend!(…);`). Signature: `dispatch_backend!($client, $c:ident, $rt:ident, $body:expr)`. Each arm opens with `#[allow(dead_code)] type $rt = <concrete cubecl Runtime>;` then runs `$body`, so a body like `launch_gemm::<$rt, F>(c, …)` resolves `$rt` to that arm's backend, while a body that ignores `$rt` (e.g. `c.create(…)`) is equally valid. The four arms carry the same `#[cfg(feature = "cuda"/"wgpu"/"rocm")]` attributes as the matching `AlgebraClient` variants.
- **`lib.rs`** — `#[macro_use] mod dispatch;` declared before the engine modules; macro stays crate-internal (no `pub use`).
- **8 engine/registry files** — all 16 dispatch sites collapsed to `dispatch_backend!` calls: gemm ×2, gemv ×1, dot ×2, axpy ×2, scal ×2, transpose ×2, reduce ×3, device_buffer ×2. The transpose/reduce statement sites keep their surrounding `if m*n != 0 { … }` / `if n_out != 0 { … }` guards and `out.shape = …` assignments verbatim. Zero `#[cfg(feature = …)]` GPU attributes remain in the 8 files — they now live only in `dispatch.rs` and `client.rs`.

## Deviations from Plan

None affecting behavior. Two observations:

1. **[Rule 3 - blocking, resolved in-plan] `unused_macros` warning after Task 1.** The plan predicted "a macro_rules! that is defined-and-unused does not warn." On this rustc it DID emit `warning: unused macro definition: dispatch_backend` after Task 1 (macro defined, engines not yet wired). This was expected-and-transient: Task 2 wired all 16 call sites and the warning vanished. No fix needed — it was a Task-1-only intermediate state, and the Task 3 clippy gate (which checks `^warning: unused macro`) is CLEAN.

2. **`type`-alias-per-arm carries `#[allow(dead_code)]`.** The plan flagged that the two `device_buffer.rs` bodies use only `c` and not `$rt`, suggesting `#[allow(dead_code)]` "only if an unused-type-alias lint fires." Rather than make it conditional, the alias carries `#[allow(dead_code)]` unconditionally in all four arms — harmless for the 14 turbofish bodies that DO use `$rt`, and it pre-empts any per-backend unused-alias lint. Single clean macro serving all 16 sites, as required.
